# P4-5d SQLite 入口与 MediaMSG 来源离线定位范围审定

总控依据本人「开工 P4-5d」推进。本卡依赖 P4-5c 的固定指纹、真实 PE 异常目录与登记源码证据，**只读磁盘定位**，不接触真实运行进程或聊天库。

可改范围：`scripts/wxhelper-db-entry-scan.mts`（离线引用扫描器）、`scripts/wxhelper-string-xref.mts`（通用字符串→引用点查找）、`scripts/wxhelper-db-entry-structure.mts`（登记偏移的入口结构判定）、`scripts/wxhelper-db-entry-candidates.mts`（从调用点反推入口候选）、`scripts/wxhelper-db-entry-verify.mts`（候选入口的结构与调用点验证）、`scripts/wxhelper-vdbe-opcodes.mts`（VDBE 操作码段检测）、`scripts/wxhelper-sqlite-version.mts`（内嵌引擎版本检测）、`scripts/wxhelper-string-map.mts`（代码区间的字符串引用映射与函数归属）、`scripts/wxhelper-column-family.mts`（从共用守卫反推列访问族）、`scripts/wxhelper-db-xref-audit.mts`（锚点引用审计驱动）、它们的测试、`docs/reports/P4-5d*`，以及本提案与报告。

后八个工具是在本卡执行中发现必要才加的，理由记录如下，请总控在合并时一并确认：

- **入口结构判定**：本卡最初的计划把登记的 `k_sqlite3_*` 偏移当作既有事实使用。执行中发现必须先回答"这些偏移是否真是函数入口"，否则后面所有身份/ABI 推理都建立在未验证的前提上。该工具只读异常目录与序言字节，不产生新偏移。
- **通用字符串引用查找**：本卡的死代码发现（`sqlite3_get_table` 链无人引用）说明"库内部字符串"不是可靠的起点，需要从应用侧字符串括出活代码边界。该工具是本卡"下一步清单"里第 1-2 步的直接工具，本轮未用它得出结论，但它是后续卡的可复用基础。
- **入口候选**：入口结构判定证明现成地址表不可用之后，必须有替代的候选来源。该工具不读任何地址表，纯从调用点行为（同一列号被传给两个不同函数）反推候选，并附结构性事实与调用点数量。**本卡据它确认了第一个真实入口 `0x3a6d90`**（64 个调用点 + ABI 证据）。
- **入口验证**：把上一条的手工验证固化为可重复检查（结构事实 + 序言原始字节 + 每个调用点的参数准备字节）。据它又确认了 `0x3a64b0`（104 个调用点），并独立复核了登记偏移 `exec` 的 0 调用点。
- **VDBE 操作码段检测**：本意是把库内 `cmp <opcode>, imm` 的常量翻成真实操作码并给版本做指纹。**结论是取不到完整表**（唯一的 `Init` 与其余名字相距很远），工具如实报告失败并拒绝输出编号。它把"这条路走不通"变成了有据可查的结论。
- **SQLite 版本检测**：对着具体版本源码比对是验证函数身份的唯一可靠办法，而版本此前并不确定。该工具用三条互证（版本串、返回版本号的函数、返回版本串指针的函数）唯一确定了 **SQLite 3.28.0**，这是本卡最有价值的单条发现。
- **字符串引用映射**：库不导出符号，所以只能靠"这段代码引用了哪些字符串"来导航。该工具给出代码区间内每个字符串的引用次数、精确位置与**所属函数范围**，据此定位到 `sqlite3_column_*` 系列的边界检查器（`misuse` 与 `API called with finalized prepared statement` 同时落在同样的三个地址上），并读出"语句指针在 RCX、错误码 21=SQLITE_MISUSE"这一 ABI 事实。
- **列访问族定位**：`sqlite3_column_*` 是唯一"取语句指针 + 列号、且必须对 NULL/finalized 语句返回 `SQLITE_MISUSE`"的一组函数，因此**它们的实现都会先调用同一个守卫**。该工具枚举守卫的调用者并按宿主函数归组，据此把列访问族从整图收敛到 8 个宿主入口，并报告各宿主的参数寄存器使用情况以区分 1/2/4 参成员。

要做到：以 SQLite/SQLCipher 内部字符串为锚点，找到代码中引用它们的**精确指令位置**，再由这些引用点读出函数身份与调用约定（ABI）；定位 BufInfoStorage/MediaMSG 的创建、注册、关闭与锁机制。

明确禁止：

- 不得把旧地址所在异常目录范围的**起点**直接当成修正偏移（P4-5c 已证明 `exec`/`prepare` 落在指令中间）。
- 不得只证明"指针可读"就开放查询；不得调用旧 `GetDBInfo`/任意 SQL。
- 不得启动、注入或卸载 helper，不读真实进程内存，不读真实聊天数据库，不调用平台或模型。
- 不得修改登记源码/偏移、构建产物或生产允许指纹；不新增迁移或依赖。

交付：可重复的引用与调用链证据，加上准入/缺失项结论。证据不足则继续 NO_GO，不因"找到了引用点"就宣称入口已确认。新补丁、接口与独立产物另行审定；实际 schema/Buf 验证由本人执行。
