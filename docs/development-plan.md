## 1. 目标：「能用」

本人确定的标准（2026-10-04）：

- QQ 和微信**同时**运行，只用**确认模式**（每条本人点确认才发）；
- 电脑开着时，**手机在局域网内**打开网页，看候选并确认发送；
- 能看懂对方发的**图片**；
- 回复**像本人**（导入历史聊天作为风格依据）；
- 暂停后能在手机上**一键恢复**；
- 手机推送提醒**不做**。

```text
已完成：P0 底座、P1 微信闭环、P2 工具、P4 多媒体/QQ 系列
现在：R1 → R2 → R3 → R4 → R5 = 能用
以后：见 §4.3
```

## 4. 任务卡

### 4.1 能用路径（R 系列）

**R1 两个平台一起跑起来**
- 要做：
  1. **修发送领错平台**：`dispatchableConversations` / `dispatchNext`（`confirmed-service.mts:461-500`）只领取本桥接账号的会话，worker 构造时传入 accountId。否则 QQ 的回复可能被微信桥接领走，结果发不出去并被记成未知。
  2. **平台标签**：联系人列表的平台按账号显示，不再用 core 的 `CORE_PLATFORM`（`confirmed-service.mts:595`）。
  3. **一条命令起全部服务**：`scripts/local-stack*.mts` 和 `scripts/local-supervisor.mts` 改为 `postgres`、`core`、`bridge-qq`、`bridge-wechat` 四个服务，两个桥接可以分别启用，端口和必填环境变量各自独立。
  4. **手机局域网访问**：
     - 已实现：core 增加 `ALLOW_LAN_HTTP=1`，显式允许私有 IPv4 HTTP 的 `PUBLIC_ORIGIN`；本机栈仅核心绑定 `0.0.0.0`，桥接与数据库保持本机监听；
     - 已实现：网页以 `crypto.getRandomValues` 生成请求编号，`@noble/hashes` 校验内容，普通 HTTP 下的手机尺寸测试已通过；
     - 本轮按本人确认的手机访问方案保持现有会话机制与时长；局域网访问支持单平台与双平台配置。
- 验收：
  - 两个桥接共用一个库，各自只发自己平台的消息；
  - 本机栈能同时起两个桥接；
  - 手机用 `http://局域网IP` 能登录并确认。
- 本人：在 `deploy/runbook.md` 的模板里填好两个平台的环境变量，手机连同一 Wi-Fi 试一下。

**R2 暂停和恢复简化**（R1 之后做）
- 要做：
  1. **QQ 手发只暂停对应联系人**：`message_sent` 不是系统回显、但 `target_id` 对应已登记联系人时，按本人发言处理，走微信 self 同样的 `PlatformSelfMessageUnattributed` 路径，只停这个联系人。`target_id` 找不到对应联系人时，维持停整个账号。改 `packages/platform/qq/onebot-codec.mts`、`webhook-ingress.mts`，以及桥接里的 `resolveSelfPeer`。
  2. **开机不暂停开关**：本机栈与本机模板默认 `START_PAUSED=0`，core 和两个桥接统一遵守；已有人工暂停、账号故障及未决发送保留。独立入口未设置时沿用旧默认值。
  3. **一键恢复**：
     - 新增「恢复联系人（清除全部原因）」和「全部恢复（所有联系人、所有可清除原因）」两个命令，各加一个网页按钮；
     - 有未决发送的联系人跳过不处理；
     - 账号故障要等看门狗记为正常后才能清除。
- 验收：QQ 手发只停一个联系人；开机后一次点击恢复全部；微信发送后的「已送达并恢复」不受影响。

**R3 图片理解接入回复**（可与 R1 并行）
- 要做：
  1. ~~提示词写入图片描述~~：已由 R4b 完成（`reply-candidates-3`）。
  2. `deploy/runbook.md` 写一份**能直接用**的环境变量模板：
     - QQ：`QQ_MEDIA_FETCH=1`、`QQ_MEDIA_ORIGINAL_VERIFIED=1`、缓存目录和媒体目录；
     - 微信：`WECHAT_MEDIA_FETCH=1`、数据目录和媒体目录；
     - 视觉：`MEDIA_VISION_ENABLED=1`、`MEDIA_VISION_API_KEY`；
     - core：`MEDIA_PRIVATE_DIR`。
- 验收：测试里图片描述进入了 DeepSeek 请求。
- 本人：两个平台各让好友发一张图，看候选有没有提到图片内容。

**R4 历史导入 + 风格**（R4b 已交付，见[报告](reports/R4b-humanlike-2026-10-04.md)：示例对话、说话习惯、图片描述、结尾提醒、拆条去 AI 腔、微信合并窗口可配；以下第 1 步 R4a 仍等 D05 样本，第 2 步中「本联系人示例」已完成，「不足时从全部联系人补」未做）
- 要做：
  1. 按样本格式写解析器，产出 `packages/data/imports/service.mts` 需要的行；加一个 PG 导入仓库和命令行 `scripts/import-history.mts`。消息以 `mode='import'` 保存，重复导入不产生重复。
  2. 生成时从该联系人取本人的历史发言若干条（live 和 import 都算）作为风格示例；这个联系人的样本不够时，再从全部联系人里补本人发言。另附一段统计出的风格摘要（平均句长、常用标点和表情、口头禅），一起放进提示词，并升级 prompt 版本。
  3. 用 `packages/ai/eval/time-cutoff.mts` 回放，对比新旧 prompt。
- 验收：导入不会触发候选或发送；提示词里出现本人示例。
- 本人：提供样本；在回放结果里抽看 10 条，判断像不像自己。
