## 3. 不能误作已确认需求

待定登记以 [decisions.md](decisions.md) 的 D01–D13 为准：接入方式、外部通知、确认后恢复方式、时序参数、导入格式、云与模型费用、保留周期、质量阈值、平台更名撤回编辑行为、分析维度阶段与更新规则、Skill 格式清单与执行能力。

§15 的具体六类维度、阶段名称、证据档位与更新窗口是建议；仅分析可展示、可纠正、可用于策略及权限不变等约束已确认。§16 的六个内置技能、Markdown/文本格式、仅指令案例和组合顺序为建议。§12 指标口径为建议，采用率 50%/80%、模型 0.90 不作为验收门槛。

## 4. 需澄清的交叉规则

| 交叉点 | 影响 | 处理建议/本次契约处理 |
| --- | --- | --- |
| 个人账号原会话 vs 官方机器人/客服账号 | 即使 API 能收发，也可能不是用户要代理的聊天 | D01 保持阻塞；不替换产品场景；先确认账号形态，再实测 |
| 自动只选启用 Skill vs 单次手动指定库中 Skill | 简单启用名单校验会误拒绝 §16.4 | 自动严格查长期列表；本人显式单次授权可用库中有效 Skill，不改长期列表；两者同样受隐私和权限约束 |
| 等待确认禁止发送 vs 确认当前方案需发送 | 若只有一个暂停布尔值，确认也会被阻止 | 待办有 reason、scope 与 plan 绑定；确认票据仅放行已解决的该方案，不绕过全局暂停/接管/未知回执等阻塞 |
| 来源删除 vs 历史版本可追溯 | 永久保留全文副本会让删除失效 | 留无正文的墓碑、ID、版本和操作记录；删去含该内容的派生正文/缓存；备份周期 D07 决定 |
| 确认后发送 vs 恢复自动 | 两者混用可能悄悄恢复自动 | 分成 confirm 与 resume 两个命令；D03 待定期间未解决待办不恢复；确认模式的后续来信仍可生成新待办 |
| 检查后立刻出现新消息 vs 已提交平台不能撤回 | 无法承诺远端绝对原子取消 | 明确本地 dispatch 边界与观察到的事件序；边界之前取消，之后记录在途/未知并停止余条；通过竞态测试和真实接入测量暴露限制 |

## 5. 关键依赖

真实接入是完整首版的首要阻塞；原平台本人发送识别、回显关联、消息同步、回执核对不可用时，自动发送不能视为可靠可用。模型与媒体样本/预算阻塞真实生成质量验证，但不阻塞契约、假模型和模拟流程。历史样本阻塞首种解析器，分析体系和 Skill 执行选择阻塞对应完整行为定稿，但不阻塞版本/证据/启用/失效框架。
