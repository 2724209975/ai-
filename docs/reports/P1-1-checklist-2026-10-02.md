# P1 同次真实闭环：本人执行清单

目的：在一次受控会话内取得真实微信来信 → DeepSeek 候选 → 本人确认 → 桥接真实发送 → 人工核对 → 恢复的证据。执行人是本人，AI 可帮助读检查结果。旧 W01 授权已使用，不能用于本次发送。

## 0. 本轮范围与授权记录

执行前在私有本机记录里填写：本轮起止时间、代码 commit、测试账号、唯一知情测试好友、模型调用次数/token 上限、测试来信。涉及真实身份、候选与正文的记录不能提交仓库。

两次检查点：

1. **准备与候选**：本人确认测试账号登录、注入/hook 和本次付费模型调用安排后，才执行下列平台操作或启动真实模型进程。建议先限制为一次来信、一次调用；上下文、输入 token 与额度由本人核对。现有单进程 UTC 日上限重启清零，核心和桥接各计一次，token 在回包后累计，不能当作跨进程/月费用硬上限。
2. **发送**：看到实际候选后，本人核对收件人、最终原文、**一条文字/一次发送**，再启动派发并点击确认。多分条候选先编辑为一条重新检查。未获当次确认时保持出站关闭，不能把候选或来信安排当作发送授权。

不得运行 `mainline-rehearsal.mts` 对接真 helper：它会合成入站、自动确认并用 fixture 证据核对；它仅供隔离离线演练。`deepseek-candidate-smoke.mts` 是另一次付费调用、临时合成上下文，不算本轮真实来信证据。本轮也不使用绑定旧 W01 数据库的 `wechat-send-once.mts`。

## 1. 工程与数据准备（离线）

确认 P0-3 通过。在 main 无待合并业务改动时记录 `git rev-parse HEAD`。本地 PostgreSQL 使用独立验收库，例如 `chat_agent_p1_20261002`，不要复用旧 send_ready、试用库或测试库中的发送任务。数据库只监听回环，不连接外部宿主。

由本人配置私有环境，不把实际值写进本清单：

| 进程 | 必要配置 |
| --- | --- |
| 迁移/登记 | DATABASE_URL 指向本轮验收库；WECHAT_ACCOUNT_ID 为本轮内部 UUID，WECHAT_SPIKE_PEER 为唯一知情好友 |
| 核心 | OWNER_ID、OWNER_PASSWORD_HASH、PUBLIC_ORIGIN=http://127.0.0.1:8787、CORE_PLATFORM=wechat、HOST=127.0.0.1、PORT=8787、START_PAUSED=1、SESSION_DIR 为私有忽略目录 |
| 接收桥接 | 同一 DATABASE_URL/WECHAT_ACCOUNT_ID；WECHAT_SELF_REF、64 位十六进制 WECHAT_INGRESS_TOKEN、私有 RAW_EVENT_DIR；HOST=127.0.0.1、PORT=19099、WECHAT_ENABLE_OUTBOUND=0、WORKER_ENABLED=0 |
| 两个模型进程 | INTELLIGENCE_PROVIDER=deepseek（核心）、WECHAT_INTELLIGENCE=deepseek（桥接）；DEEPSEEK_API_KEY 私有注入；DEEPSEEK_DAILY_CALL_LIMIT / DEEPSEEK_DAILY_TOKEN_LIMIT 是本人同意的正整数；DEEPSEEK_THINKING=disabled |

密码哈希使用现有 `npm run owner:password` 从私有输入生成；不要把明文写在终端命令或报告里。核心和桥接使用不同的私有日志文件，两个模型都必须明确选择 DeepSeek，避免补处理走 fake。

依次执行：

```powershell

node scripts/wechat-spike-enroll.mts
```

期望：迁移至 0010；仅登记一位测试好友，输出 enrolled=true、sendEnabled=false。登记脚本不幂等，**只跑一次**；失败后先检查实际记录，不盲目重跑。网页稍后检查代理开启、确认模式、时区 Asia/Shanghai。

## 4. 解除本轮暂停，接收一条真实测试来信

本人在网页核对唯一联系人与确认模式、无未决发送后，显式解除全局暂停；若有联系人暂停，核查原因并逐项恢复。未知发送不能靠恢复绕过。记录 P1_START（含 +08:00 或 Z），由知情测试好友从原客户端发一条无私人信息的文字。

检查：桥接出现 ingress-inserted；本轮数据库有 live/text 来信并有平台消息 ID；网页出现该来信对应的新待办。切勿通过合成 HTTP 推送或旧原始字节重放代替真实来信。

两个私有模型日志合计只应有一次 model_call，providerId=deepseek、outcome=ok，token 与时延可见；待办有非空候选，允许 confirmPlan。出站仍关闭、发送任务仍为零。若来信在暂停时到达，可以恢复后由本人点击「为最新来信生成候选」，但必须记录这一步且不能重复生成；模型上限不足时停止、核查预算，不重启绕过限额。

候选不可用、出现多次模型调用或多个联系人/方案时，暂停并调查；对账脚本不会替本人推定哪次模型调用对应哪个方案。

## 6. 本人核对送达，再记录并恢复

先看好友原客户端是否确实收到唯一一条最终文字。看到「只收到 1 条」后，本人在会话页填写不含身份/正文的证据引用，例如 `p1-20261002-owner-check-01`。

- 选择「已送达并恢复」：原子记录人工核对并清除 UNKNOWN_SEND。其他暂停、全局暂停和代理关闭不随之清除；只有没有其他原因时才回到 READY_CONFIRM。
- 或选择「只记已送达」后，再按实际暂停原因显式恢复联系人。
- 明确失败才记 FAILED_DEFINITE。无法判断时仍保持 RESULT_UNKNOWN 与暂停，不能猜失败，不能重试。

没有平台消息 ID 时保持空值；人工核对不变成平台自动回执。恢复后复查发送数量仍为 1、attempt_count 仍为 1，不补发。

## 7. 只读对账与报告

为本轮记录 P1_END（显式时区），设置 P1_ACCOUNT_ID 为本轮内部账号 UUID；只读工具使用同一 DATABASE_URL。两个模型日志都传入，且不要重复传同一个日志文件：

```powershell
$env:P1_ACCOUNT_ID=$env:WECHAT_ACCOUNT_ID
$env:P1_START='<本轮开始时间，含时区>'
$env:P1_END='<本轮结束时间，含时区>'
node scripts/p1-mainline-audit.mts '<本轮核心私有日志>' '<本轮桥接私有日志>'
```

输出仅包含内部方案/待办/发送/关联 ID、匿名联系人序号、状态、次数、摘要是否一致、核对证据是否存在以及模型调用数字，不输出正文、联系人身份、平台消息 ID、证据原文或凭据。工具在 REPEATABLE READ / READ ONLY 事务内查询，不写库，不登录管理端，不连接微信或模型。

验收对账：一联系人、一真实来信对应方案、一个成功模型调用、一个已解决待办、一个已确认方案的发送；发送与账本状态一致、sameContentHash=true、attemptCount=1、evidencePresent=true、resolutionCount 至少 1；核对后 unresolved=false。联系人恢复和全局停止是不同证据，最终是否暂停按实际记录。

**关联限制**：现有 model_call 没有 planId/correlationId，工具的 modelLink 固定为 time-window-only；isolatedSingleRunShape 仅代表一个方案/一个成功调用的形状，不证明精确关联或真实送达。必须用全新验收库、单联系人、单来信及完整日志窗口人工核对。日志缺失、重复或额外调用时不能判通过。

报告 `docs/reports/p1-real-mainline-<日期>.md` 记录：commit、契约版本、客户端/helper 指纹前缀、模型预算与 token/时延、各步骤结果、内部 correlationId、一次发送与人工核对证据、异常与限制。报告不含正文、真实身份或私有路径。P1 是否通过由本人判定，42 条完整 AC 和自动发送能力不自动升级。

## 8. 正常结束与异常停止

任何异常优先按此顺序：

1. 本人在管理网页点全局暂停，刷新确认 globalPaused=true；不要自动恢复。
2. 本人在已核验真 helper 上卸载消息 hook：

   ```powershell
   Invoke-RestMethod -Method Post -Uri http://127.0.0.1:19088/api/unhookSyncMsg -ContentType application/json -Body '{}'
   ```

   期望 code=0。这只是卸载接收 hook，不等于卸载整个 DLL。helper 无响应或微信已退出时不要反复调用，记录异常并停止本轮进程。
3. 在本轮终端停止桥接、核心；关闭自己本轮创建的隔离数据库服务，保留库、私有日志及原事件。不能停止不属于本轮的服务或把私有证据加入 Git。

若管理网页不可用，立即停止本轮桥接阻止后续派发，再处理暂停与证据；不能为了满足正常顺序而继续运行失控派发进程。已跨提交边界的消息无法撤回，按未知事实保留，不清账本、不重试。

正常完成也执行全局暂停 → unhookSyncMsg → 停本轮进程。最终环境保持出站关闭，下次运行重新确认。保留数据用于复核，不把本次闭环扩成长期运行或自动模式。
