# 微信与 QQ 真实接入验证计划

状态：2026-09-22 仅完成公开资料初查，两个平台对“本人现有个人账号的一对一好友会话”的能力均未实测、未确认。任何 mock、机器人或客服 API 的成功都不能替代目标账号场景的真实验证。

## 1. 当前查证结论

QQ 官方机器人文档说明：用户可与“机器人”单独对话，提供单聊收发、文本/富媒体、主动与被动消息、重复事件处理等规则；被动单聊消息有时限/次数约束，用户也可关闭机器人主动消息。官方 BotGo 示例同样要求创建 QQ 机器人及沙箱成员。这证明“机器人账号场景”有官方服务端接口，不证明它能读取或代发本人普通 QQ 账号与既有好友的聊天。[QQ 启动接入](https://bot.q.qq.com/wiki/develop/api-v2/)、[QQ 消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)、[BotGo 官方仓库](https://github.com/tencent-connect/botgo)。

微信方面，本轮未取得可直接支持“个人微信现有好友会话自动收发”的官方资料。企业微信/微信客服、公众号或小程序均属于不同账号/会话形态，除非实测证明满足目标，否则不能拿它们替代个人好友聊天。第三方桌面注入、逆向、协议模拟等路线还涉及封号、条款、稳定性与云端登录风险；在本人明确接受风险且完成隔离测试前，不列为已选方案。

QQ 路线的候选版本、许可与入口缺口已整理为 [QQ spike 计划](platforms/qq-spike-plan.md)（2026-09-24，仅只读查证，未安装、未登录）。更细的候选对比和只读开源评审见 [platforms/feasibility.md](platforms/feasibility.md) 与 [platforms/github-reuse.md](platforms/github-reuse.md)。其中 QQ 的 NapCat/OneBot、微信的 openclaw-weixin、Wechaty、WeChatFerry 等都只是调查候选：维护者声明、代码可见和开源许可不能证明平台授权、账号稳定或满足本人现有会话。若引入，必须固定版本、复核许可证并走本文件的真实 spike。

公开文档会变化，以上只作 spike 输入。每个平台必须保存实验日期、账号类型、客户端/adapter 版本、原始事件（脱敏）、平台响应、视频/日志证据和限制。

## 2. 首先必须回答的问题

| 维度 | 必答问题 | 通过标准 |
| --- | --- | --- |
| 身份 | 连接的是本人现有个人账号、机器人、客服还是新账号？对方看到谁？既有好友无需迁移吗？ | 与本人确认的目标账号形态一致 |
| 合规/风险 | 是否官方允许自动化？账号被限制/封禁概率与恢复路径？是否需要企业/实名/审核？ | 风险由本人明确接受；不得隐瞒非官方路线 |
| 关机 | 本人电脑关机 24h 后登录会话是否继续？是否依赖手机、Windows、二维码重扫或常在线设备？ | 关机测试期间持续接收、处理、发送；依赖项如实记录 |
| 入站 | 一对一文字、图片、语音、静态/动态表情能否收到稳定 ID、顺序、时间、引用、来源？重复/乱序表现？ | 每类型有原始样本和归一映射；缺项能明确报 unsupported |
| 媒体 | 能否下载原图、原语音、完整动态内容？URL/token 失效期？大小/格式限制？ | 可私有保存并复现理解输入；动态不只取任意单帧 |
| 出站 | 能否发文字、多条文字、已批准表情；回复/主动发送窗口和频率；是否能提供 client idempotency key？ | 约束可机器表达；越界明确失败 |
| 回执 | “API 接受、平台入库、对方可见”分别有哪些证据？超时后能否按 sendKey/消息查询？ | 能区分明确失败和未知；未知时阻塞而非重发 |
| 本人发言 | 如何区别本人手发、系统发送及平台回显？多个设备是否一致？ | 测试集无混淆，或明确缺口并禁用自动模式 |
| 连接恢复 | token/扫码/设备锁/版本升级/断网后如何恢复？是否丢消息？可否从 cursor 同步？ | 恢复先同步与 reconcile，不补发旧回复 |
| 变更 | 撤回、编辑、删除、改名、引用缺失能否收到？ | 映射 D09；缺失时标能力限制 |
| 安全 | webhook 验签、token 轮换、IP 白名单、最小权限、凭据存放？ | 伪造/重放被拒绝，凭据不入日志/仓库 |

## 3. 候选路线记录

| 路线 | 当前证据 | 是否匹配既有个人聊天 | 状态 |
| --- | --- | --- | --- |
| QQ 官方机器人 | 官方文档支持用户与机器人 C2C，含消息/媒体/主动规则 | 暂无；身份是机器人 | 可做官方 adapter spike，目标适配未验证 |
| 普通 QQ 个人账号官方接口 | 本轮未找到可确认资料 | 未知 | 未验证 |
| 微信个人账号官方接口 | 本轮未找到可确认资料 | 未知 | 未验证 |
| 企业微信/微信客服/公众号 | 属于不同产品和会话形态 | 默认不匹配，需本人明确改变场景才讨论 | 非默认方案 |
| 第三方协议/桌面自动化/注入 | 本轮未采信供应商声明 | 可能表面匹配，但关机、封号、回执、本人识别风险高 | 不选择；若评估需单独风险决策 |
| 专用常在线设备桥接 | 取决于具体实现 | 可能匹配，但“本人电脑关机”不等于无设备 | 候选架构，需本人接受并实测 |

2026-09-24 复查（GitHub API 可用后）：微信侧能匹配「本人个人账号 + 既有好友会话」的候选只剩非官方 Hook 或 UI 自动化，分别受**无许可文件**、**GPL-3.0 传染性**、客户端版本强耦合与**必须另备常开 Windows/macOS 宿主**的限制；原先两条主力路线已失效（WeChatFerry 归档、Wechaty 微信 puppet 停更四年）。完整事实、更正与三个决策选项见 [wechat-route-options.md](platforms/wechat-route-options.md)。

2026-09-24 当晚进展：本人选定 **wxhelper** 路线。上游三份偏移表在本机 `WeChatWin.dll`（腾讯签名有效的 3.9.11.25，SHA-256 `2058A926…`）上都崩宿主，离线核查证明那是**同版本号的另一个构建**；随后按本人授权完成**离线偏移移植**（自建 Capstone 反汇编工具链，定位并交叉验证 `kDoAddMsg=0x230ef30`、`kGetAccountServiceMgr=0x1b557d0`，并确认 `AddMsg` 字段偏移与上游一致），注入后**只接收实测通过**：`checkLogin` 返回 `code=1`、`hookSyncMsg` 返回 `code=0`，知情好友发来的 5 条事件全部捕获且 5/5 带平台消息 ID（文字×2、图片、语音、type 51『拍一拍』），微信未崩溃。因此微信侧不再是"未验证"：`receive_types` 为 `tested`，发送/回执/本人回显/历史补齐/媒体完整获取仍为 `unknown`。记录见 [platform-wechat-wxhelper-2026-09-24.md](reports/platform-wechat-wxhelper-2026-09-24.md)。注意：**其余 83 个偏移仍是上游值，调用其它接口可能崩宿主**；微信每次更新都要重做偏移移植。

## 4. Spike 执行与报告

每平台独立限时实验，先沙箱/测试账号，不在主账号直接试高风险方案。步骤：锁定账号形态和官方条款 → 建最小 adapter → 执行能力矩阵 → 制造重复、乱序、断网、超时、进程崩溃 → 关本人电脑持续测试 → 恢复并 reconcile → 产出 go/conditional/no-go。

测试至少包括：双向文字；各媒体类型；多条消息；主动消息；本人从手机/桌面发言；系统回显；同一事件重复；发送前断线、提交中断线、接受后丢响应；adapter/核心/数据库分别重启；二维码/token 过期；平台限频；24h 本人电脑关机。正式 AC23 的持续时长与可用性目标由 D06 确认，24h 只是 spike 下限建议，不是 PRD 新承诺。

报告写入 `docs/reports/platform-<platform>-YYYY-MM-DD.md`，并同时交付同日的 `platform-<platform>-capability-snapshot-<date>.json`（格式与填写规则见 [QQ 只接收步骤](qq-receive-only-runbook.md) 与 contracts.md §2；总体状态由逐项证据推导，`tested` 不得只引用厂商文档）。报告包含：路线/版本、环境、能力快照、逐项证据、风险、成本、人工维护频率、未验证项、结论、对 contracts 的变更提案。结论为 `GO_CONFIRM_ONLY`、`GO_AUTO`、`CONDITIONAL` 或 `NO_GO`；只有满足本人发言识别、未知回执处理和关机持续运行后才能 `GO_AUTO`。

## 5. 开发期间的模拟 adapter

mock 必须支持文字入站、媒体引用、本人发言、重复/乱序事件、平台回显、延迟回执、明确失败、`RESULT_UNKNOWN`、断线/恢复、能力缺失和虚拟时钟。测试输出必须标记 `adapter=mock`；验收报告把 simulated 与 real 分栏，禁止把 mock 结果计入平台通过数。
