# 普通电脑、QQ、微信与手机共用费用账本

普通 Core、QQ Bridge、微信 Bridge、Owner 开发入口及双平台手机联动现在接入同一套文件账本。手机仍直接调用自己的模型；分配给手机的离线额度先从电脑可用金额扣除。Android 0.7.1 的协议兼容此次电脑更新，无需更换手机包。

## 配置与启用

1. 保留当前费用文件及私有配置，停止要升级的相关进程后统一更新代码。所有普通入口必须使用同一份配置、同一个绝对账本路径，再一起重启；不要混用更新前后的计费代码。
2. `MODEL_SHARED_BUDGET_PATH` 指定共同的私有文件，优先级高于旧 `DEEPSEEK_SHARED_BUDGET_PATH`。旧路径仍兼容，优先继续用旧文件；都未填写时，正式入口使用当前工作目录下 `.local-model-budget/shared.json` 的绝对路径。这个目录不进仓库。不同工作目录要显式填写同一个绝对路径。
3. `MODEL_TOTAL_CNY_LIMIT` 是本次账本的累计上限，`MODEL_DAILY_CNY_LIMIT` 是电脑每天的金额上限。未填写时沿用已配置的 `DEEPSEEK_DAILY_CNY_LIMIT`；金额均未配置时为 0，不能发起新的收费调用或分配手机资金。不会自动补成 10 元。
4. 总额度必须来自之前授权、仍未分配给其他试用的资金。原 QQ 候选试用的专用 `calls.jsonl`/数据库账本保持原样，不能把它尚可消费的钱同时分给普通入口。不同账本不自动合并或重新授权；转用普通入口时，先核对原试用剩余及未结费用，停止原试用后再配置对应金额，不清零旧账本。
5. `DEEPSEEK_DAILY_CALL_LIMIT`、`DEEPSEEK_DAILY_TOKEN_LIMIT` 控制电脑共享每日次数/用量，额外保留原各模块限制。普通 QQ、微信和后台模型的累计费用与手机额度共用同一总限额，跨天只重置电脑每日计数，累计费用与离线分配不重置。
6. 旧回复与背景选取填写 `DEEPSEEK_INPUT_CNY_PER_MILLION`/`DEEPSEEK_OUTPUT_CNY_PER_MILLION`；v2 高低模型用注册项自己的人民币价格快照；图片填写 `MEDIA_VISION_*`，语音填写 `MEDIA_VOICE_*`，已授权启用的 embedding 填写 `MEMORY_EMBEDDING_INPUT_CNY_PER_MILLION`。价格单位均为元/百万 token。未知价格、非人民币的 v2 价格不会猜汇率，会阻止上传。

配置模板见 `deploy/unified-budget.example.ps1`，示例金额和价格都是 0，使用前按既有授权填写。模板不包含密钥，不启用任何模型、媒体、embedding 或真实发送。

## 费用与兼容规则

- 网络请求前，以文字字节上界、输出上限和各模型价格做保守预留；图片暂用 65536 token 加协议余量，语音按原字节上界保守预留。未知模型计价仍需核对。这不是供应商账单。
- 失败、超时、取消、进程退出不回补已预留费用；后台背景选取和授权启用的 embedding 也占同一份额度，默认关闭的功能不会因此启用。
- 首次升级会把旧文件当前保留的 `reservedMicros` 纳入累计电脑预留，原每日计数保留。旧格式只保留最后一日，不能从它恢复更早已经丢失的历史账单，启动前需结合原试用记录核对授权余额。
- 累计金额上限和每日共享政策在第一次配置后固定；各进程配置不一致会报错，不能通过重启或改大环境数值偷偷补额度。初始 0 元、尚无分配或调用的未配置账本，可以在私有配置中完成首次金额设置。
- 多进程使用同一文件锁和原子替换；损坏或进程崩溃遗留的锁会阻止新调用，不猜测清锁、不另起空账本。
- 分配是累计额度，只能增加，不能在手机可能离线消费时回收。断开、撤销、换平台或恢复备份不归还资金。手机上报不能倒退，设备只看到自己的分配；Owner 的总览看到两端合计和电脑当日计数。
- 若数据库中已有旧 QQ 试用的离线分配，普通入口不会覆盖它，必须继续使用原账本或另行对账迁移。

在普通电脑或微信工作台「手机联动 → 两端费用与额度」查看总额、电脑预留、手机已上报消费、当日调用及剩余额度，分配后手机同步领取。费用不足或价格/账本异常会结束本轮任务并提示原因，不走模型失败降级，不创建可发送的候选。

本轮交付是源码、配置模板及离线验证。当前正在运行的旧实例未自动替换，没有新收费请求，也没有启用自动发送。
