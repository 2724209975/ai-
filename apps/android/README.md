# 安卓回复助手

当前定位（2026-10-12）：原生手机 App 独立辅助起草，每次生成 3 条候选，由本人复制、粘贴发送。手机聊天原文同步给电脑，电脑长期记忆同步给手机；手机采用与电脑同阶段、同决策契约的 v2 生成流程，生成任务不转发给电脑。0.7.1 新增费用与调用记录、QQ 试用离线额度、加密备份及恢复预览、模型配置检查与生成依据说明。详见[使用与升级指南](../../docs/mobile-setup-and-upgrade.md)。

电脑后续已补齐普通 Core/QQ/微信共享费用接线，仍兼容本版手机。统一部署和配置见[共用费用指南](../../docs/unified-budget.md)；原 QQ 候选专用账本保留，不自动授予第二份同额预算。

0.7.0 继续移除填入输入框和通知发送能力，保留读取聊天和复制；下方旧版本记录中的填入/快捷发送不代表本版本能力。构建、JVM、Lint 及设备测试包编译通过，本轮没有安装到手机或运行设备测试。

独立原生 Android App，运行与保存都在手机上；生成回复时由手机直接调用模型接口，不要求电脑在线。可选电脑联动将已同步资料缓存到手机，电脑离线时仍可使用。目标手机为红米 K80 Ultra / 澎湃 3.0.3 / Android 16，最低 Android 14。详细需求见 [手机需求](../../docs/android-requirements.md)。

手机起草不调用电脑生成接口；电脑离线时使用已下载资料，仍需手机联网访问配置的模型。当前 QQ 试用工作台的「手机联动」已接入新同步服务；旧日常库的配对凭据不能直接用于试用库，需要重新配对并关联同一对象。详见[交付与设置说明](../../docs/reports/mobile-independent-v2-2026-10-12.md)。

## 安装与首次使用

构建产物：`output/android/reply-assistant-0.7.0-debug.apk`。这是供个人安装试用的 debug 包，不是商店发布包。手机需要允许从对应文件管理器安装应用。可覆盖旧版安装，保留模型配置、档案和草稿。

1. 安装 APK，打开「设置」，填写「截图识别模型」的 HTTPS Chat Completions 地址、支持图片输入的模型名称及自己的 API Key，点击「保存模型配置」。支持完整地址，也支持根基础地址或 `/v1` 等版本基础地址，自动追加 `/chat/completions`，不探测其他主机或重试；例如 `https://api.deepseek.com` 可直接填写。带自定义路径的服务请使用其完整接口地址。旧版图片模型配置直接沿用；只有旧版文字模型配置时，需要补充多模态配置，不会假设文字模型支持图片。
2. 展开「低成本决策与日常回复模型」，配置低成本接口、名称和 Key；原有文字配置保留，未配置文字 Key 时沿用截图模型进行纯文字决策和日常生成。在「高档回复模型」填写另外的接口、名称和 Key，复杂场景由手机直接调用。保存设置。
3. 在「待回复」选择截图，或从系统相册将截图分享给「回复助手」。首次选择聊天对象、同意截图发送到自己的模型服务后，自动生成；之后沿用所选对象。首次截图通常先识图一次，再决策一次和生成一次；已经识别或纠正的截图重试、改写时只走后两步。文字直接走决策和生成。默认不使用 OCR，不逐条勾选。
4. 复制回复，在原聊天发送。复制不会标为发送；你可点击「我已发送」记入正式上下文。
5. 点首页「开启悬浮助手」，未允许悬浮窗时先进入授权页面，允许后返回。可在设置允许运行通知。悬浮「回复」点击或长按均只打开回复面板，再点击面板顶部「截屏」获取画面。首次经系统许可后，同一会话内可连续点按截图；每次只保存一帧，随后暂停画面接收，保留授权供下次点击。闲置五分钟、关闭助手或通知栏「结束连续截图」会结束会话。锁屏、系统终止或会话结束后需要重新授权。截图直接交给模型理解并起草回复。
6. 若要读当前聊天，开启无障碍。回到目标聊天，打开悬浮面板后点「读取聊天」。无障碍不填写输入框或点击发送；回复由本人复制后粘贴。
7. 若要处理微信／QQ 通知，开启通知读取，并在发现列表确认启用对应单人聊天。只有提供稳定会话标识的通知才能连续归档；缺少标识时每个事件都需重新确认，避免同名串人。未启用时不落盘消息正文，进程结束后未确认的通知正文会丢失。

回复面板同时列出三条完整建议，点选后即可编辑，底部「复制」始终可见。复制后默认收起，可在设置关闭；不会记为实际发送。切换候选会保留已有手工稿，「恢复旧稿」可恢复。建议下方提供「短一点」「自然一点」「重写」，继续使用本轮图片和上下文，不用重新截屏。新一轮开始时保留旧建议，成功生成后替换，失败可重试；旧的未使用自动候选不积累到历史草稿。

顶部小下拉按钮选择对象，「记录」在面板内展开最近六条保存原文，并可「查看全部」。获取内容保留「截屏」，新增「读取聊天」：只读取主动选择的外部界面可见非密码、非输入框文字及控件位置，由已配置多模态模型先整理对话，再按手机 v2 流程生成三条建议；不依赖 OCR，不逐条核对。读取不到、来源不明或图片未提供实际内容时提示改用截图，暂不承诺微信/QQ完整历史读取。首次上传说明同时涵盖截图和主动读取的界面内容。

截图模糊、背景缺失或明显属于另一对象时提示补图或切换对象。每个对象本轮图片、补充文字、要求和草稿分别保留，切回自动恢复，切换本身不生成或上传旧图。最多保留四批其他待处理内容，结束本次时清除原始来源。自动生成不会覆盖本人修改的草稿，需显式重新生成。生成后显示本轮新增与匹配已有数量；仍按连续片段去重，不按相同文字全局删除。识别原文、说话人、截图顺序、追加截图及本地 OCR 收进「补充／纠正」。

通知只用于接收本人启用对象的聊天内容，不保存或执行原通知的快捷回复动作。手机仅生成候选，由本人复制、粘贴和发送。

## 本地数据和上下文

- SQLite 存档案、原文、带来源的较早聊天摘录、草稿和本次预览，写入为原子事务；Key 使用 Android Keystore AES-GCM 加密，不进入聊天库。
- 本地 OCR 使用随 APK 打包的 ML Kit 中文模型，仅为可选辅助工具；截图主流程不调用它。多模态配置缺失或失败会提示重试，不自动切换到 OCR 或文字模型。
- 聊天对象由本人首次选择并沿用，顶部始终显示名称，可以切换；不会凭昵称自动选择对象。多张截图同一次请求逐页识别，只合并可靠的连续重叠，单个无时间的「好」不会被删。
- 摘要目前使用可追溯的原文摘录，避免生成额外事实；修改原文会重建摘录并使旧候选失效。
- 模型识别的原文保留来源和不确定标记；不确定内容不进入事实摘要或本人风格样本。纠正历史原文会同步到保留的截图纠错结果，重写时不会恢复被删除的行。
- 建议、复制和填写均为草稿。多模态识别不会自动把草稿标成已发送；本人点击「我已发送」后才记入。
- 原始截图留在私有缓存中的本次处理，可追加和重写，重启可恢复；App 面板点「完成」或折叠区点「结束本次」删除原图，保留识别文字和必要图片描述。悬浮「收起」暂时保留，再次打开可继续。删除档案会删除其原文、摘录和草稿。
- 系统备份及设备迁移排除本应用数据。可选电脑联动只同步本人关联对象的资料，详情见下方「电脑联动」。

## 构建和检查

需要 JDK 17+、Android SDK platform 36.1 / build-tools 36.1.0。Gradle wrapper 随工程提供，依赖版本固定。

Windows 推荐从项目根运行：

```powershell
.\scripts\build-android.ps1
# 已连接 Android 14+ 的隔离测试设备/模拟器时：
.\scripts\build-android.ps1 -DeviceTests
```

脚本使用用户缓存目录中的 ASCII 路径构建副本，避免 Windows 下中文项目路径导致 JVM 单元测试 classpath 失效，不清理或重置共享工作区。复制、APK、JVM 测试、Lint 和设备测试包生成通过后，APK 导出到 `output/android/`。设备测试会安装独立的离线合成聊天夹具，使用隔离存储，并临时启用测试用无障碍和悬浮权限后恢复；不登录或发送真实平台消息。多个设备连接时先设置 `ANDROID_SERIAL` 选择测试设备。不要在日常使用中的手机上运行设备自动测试。

初版验证见 [M1 交付报告](../../docs/reports/android-M1-2026-10-07.md)；当前多模态版验证见 [多模态调整报告](../../docs/reports/android-M2-2026-10-07.md)。

0.2.1 的基础地址补全与真实模型验证见 [红米真实模型报告](../../docs/reports/android-M2-live-model-2026-10-07.md)。合成截图上的真实模型调用已通过，不表示所有聊天软件或图片场景已经验收。

其他系统在 `apps/android` 配置 SDK 和 Java 后运行：

```text
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest
```

安卓工程不改电脑端的接口或数据迁移；现有 `npm run verify` 不包含安卓检查。

## 真机验收

现场试用留待本人安排：选图或分享 → 首次选人及上传提示 → 看图生成 → 多图重叠 → 档案切换 → 原文纠错重写 → 复制 → 我已发送 → 重启恢复；再查看悬浮截图、锁屏恢复、主动读取可见聊天和通知。微信、QQ、另一个聊天界面分别记录识图与复制是否可用。权限撤销时手动分享和复制仍可用。手机不自动填写或发送；不要把模拟接口测试当作真实模型识图质量验证。

澎湃系统的自启动、省电和后台限制以及实际聊天应用的节点/通知格式，需要在目标手机验证。模拟器通过不代表这些兼容性已通过。真实平台登录和真实发送由本人操作。

参考：[中文 OCR](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)、[单次投屏与授权](https://developer.android.com/media/grow/media-projection)、[AGP 8.13 / API 36.1](https://developer.android.com/build/releases/agp-8-13-0-release-notes)。


## 个人风格、反馈与狗头军师（0.3.0）

- 回复面板新增“太长了、不像我、语气不对、事实不对”。前三项直接重写，事实纠正后再重写；只有主动“记住这个偏好”才影响以后的回复，可选当前对象或所有对象并编辑、删除。
- “补充／纠正 → 我的表达样例”可标记可靠的本人发言。截图发言不会自动成为样例，AI草稿不能学习；至少十条可靠样例才加入风格统计。“历史手工草稿”可恢复旧稿，恢复后需核对最新上下文。
- “聊天档案 → 编辑”可按对象启用狗头军师。启用后截图仍一次看图并出建议，分析折叠展示。回复面板和档案卡的“问军师”进入独立咨询，支持问题、背景、截图及多轮讨论。“用作回复”只创建草稿，不发送。
- 在军师页展开“关系档案与记忆”，明确同意后才自动保存精简关系记忆，更新会提示；支持暂停、撤销和删除。未知信息不补成事实，MBTI和评分可选。
- 原始咨询截图失败时保留、成功后删除；识别记录与咨询长期保存在所属对象，可清除。内置固定版本狗头军师及参考资料，资产含原MIT许可证，不依赖电脑服务，不执行技能脚本。

## 透明度与回复速度（0.3.1）

「设置 → 悬浮透明度」分别调整悬浮按钮和回复面板，透明度范围为0%～80%，拖动即时生效，松手保存。普通应用页面保持不透明。调整不会使正在生成的回复失效，也不会清除尚未保存的模型输入。

「优先快速回复」默认开启，修改后点击保存设置。截图上传前按比例压缩到最长边2560像素、JPEG质量85；请求避免重复提交当前截图已识别的原文，仍保留用户纠错、此前聊天和三条候选。开启快速回复时精简日常军师分析；独立咨询仍使用模型默认思考方式。仅对官方 `api.deepseek.com` 的已支持型号设置 `thinking.type=disabled`，其他服务不注入专有参数，参见 [DeepSeek 参数说明](https://api-docs.deepseek.com/guides/thinking_mode/)。生成完成提示显示本次处理耗时；它不包含截图授权时间，不能视为普遍速度承诺。

构建与验证记录见 [0.3.1 报告](../../docs/reports/android-M3-speed-2026-10-07.md)。

## 精简面板与连续截图（0.3.2）

悬浮面板缩至约半屏，默认显示对象、可编辑建议以及「填入／复制／换一个」。「更多」展开快捷反馈、偏好、军师分析、重写要求和「补充／纠正」。错误、事实不确定和草稿过期提示仍直接显示；首次选人及上传说明保留。等待生成时可以收起悬浮面板。

截屏授权在有效会话内复用，不缓存授权令牌供后续会话使用，不绕过系统授权。系统保留共享状态提示；通知栏可主动结束连续截图。每次点击才接收并保存一张图，两次点击之间断开画面接收，闲置五分钟自动释放会话。再次授权仍需由本人在系统弹窗操作。

0.3.3 将悬浮回复面板固定在上半屏，宽度94%、高度48%，顶部留8dp间距，便于查看和操作下方聊天输入框。

0.3.4 顶部改为小对象下拉按钮、截屏和收起；悬浮按钮仅打开面板。三条模型建议同时列出供点选，选中项高亮，编辑按需展开。沿用同一会话连续截屏及既有草稿保护。


## 顺手操作（0.3.5）

- 保持上半屏面板，填写、复制和编辑固定在底部；选中的候选展示全文，编辑直接位于选中项内，候选与更多内容单独滚动。
- 复制成功自动收起；填写失败提供「复制并收起」，复制和填写仍不记为实际发送。
- 「截屏」开启新一轮，「补充前文」追加当前轮；顶部显示本轮张数。已确认聊天保留，旧批次尚有未处理内容时暂存，在更多中恢复；最多暂存四批，达到上限会提示先处理，恢复时回到原对象。手工草稿不会被自动生成覆盖。结束本次删除所有本次原图。
- 悬浮按钮可拖动，松手贴边，记住位置；拖动不会打开面板或截屏。对象下拉支持名称／平台搜索，按最近使用排列，同名对象显示平台。
- 悬浮「问军师」进入 App 全屏咨询，输入区固定底部，可补充背景与截图，新回答出现时滚到最新一轮。

验证与限制见 [0.3.5 报告](../../docs/reports/android-M6-usability-2026-10-07.md)。


## 清理未使用候选（0.3.6）

开始新一轮「截屏」时，删除当前对象未编辑、未复制或填入的上一轮自动候选，不转存历史草稿。补充前文不清理；手工稿、已复制或填入的稿件以及发送状态待核对的稿件保留。新的生成结果仍直接替换当前自动候选，失败保留本轮截图供重试。

## 电脑联动（0.4.0）

「设置 → 连接电脑 / 同步资料」配对后，手动选择要关联的手机档案与电脑联系人。电脑负责整理长上下文、表达习惯及编辑关系背景、偏好；手机保存整理资料，电脑关闭时仍可供手机回复使用。不同对象和平台隔离，冲突主动选择；不上传原始截图、未采用候选、草稿或咨询记录，也不共享模型 Key。

同一 Wi-Fi 首版、安装与验证情况见 [交付报告](../../docs/reports/mobile-desktop-link-2026-10-08.md)。真实对象首次关联由本人选择。

## 聊天记录（0.4.1）

档案卡片增加直接查看聊天记录的入口；回复面板顶部点「记录」进入全屏记录页。双方发言以气泡展示，合并显示手机已保存内容与电脑同步原文，支持搜索、复制、补充和纠正手机记录。草稿不会混入发言，查看记录不触发模型生成。

这里展示的是已截图、接入或同步的内容，不能自动读取聊天软件完整历史。[优化与验证报告](../../docs/reports/android-history-2026-10-09.md)。

## 截图去重与顺序（0.4.2）

截图可与已有记录中间的连续窗口对齐，重复截屏复用原记录，补前文和后文按已知重叠位置合入。图片说明不阻断对话匹配，无时间截图不再被查看页统一排到已发送记录之前。

已有重复在记录页点「整理重复」，预览并确认后合并，保留原记录供撤销及手工草稿；无法确定的相同表达不自动删除。纠正界面可上移记录、确认顺序。[修复报告](../../docs/reports/android-dedup-2026-10-09.md)。

## 手机回复体验（0.5.0，第一批与第二批）

- 悬浮面板默认约半屏，拖动顶部横条调整高度并保存。编辑时隐藏截屏／读取按钮，为候选和底部操作留出空间；键盘出现时按实际可见区域调整面板，填入、复制和完成编辑保持可见。
- 在同一次 App 运行中，收起再打开、切换对象、查看记录后返回会恢复各对象的阅读位置、编辑状态和展开内容。每条候选分别保存手工修改，切回时继续原稿；手工文本随档案保存，进程重启后仍可恢复。
- 生成显示实际处理阶段与已等待秒数，支持取消；取消和失败保留本轮截图及原稿，可直接重试。仍保持一次模型请求识别内容并返回三条候选。
- 面板显示对象平台、最近保存的一句话及资料同步时间，点最近内容可展开上下文，查看全部后回到回复继续编辑。
- 提示模型返回三种不同的回复策略及简短标签，第一条优先贴合本人习惯，其他候选体现不同回应思路；重写带上当前手工文本。个人表达样例优先选择与当前话题相关的真实对话，不采用 AI 草稿或不确定样例。

验证与实际使用限制见 [0.5.0 交付报告](../../docs/reports/android-mobile-flow-2026-10-09.md)。

## 电脑联动体验（0.6.0，第三批）

在「设置 → 连接电脑 / 管理资料」进入独立联动页面；回复面板「更多 → 电脑资料 / 同步」直接打开当前对象。

1. 电脑与手机连接同一 Wi-Fi，在电脑「更多 → 手机联动」生成配对二维码。手机拍摄二维码或粘贴配对内容；失败时保留粘贴内容。电脑配对码显示剩余时间，过期后重新生成。
2. 选择手机对象，搜索同一人的电脑联系人（名称和平台都可查），点击「关联当前对象」。也可选「仅整理手机资料」，让电脑只处理该手机档案。
3. 可以同步当前对象或全部关联对象。手机显示待同步修改数、成功更新时间及可读的冲突版本，选择后继续同步。同步过程中新增的手机修改会保留并续传；只有上传确认时，不会使原回复草稿过期。
4. 「手机已下载资料」显示按当前话题选取的较早原文、来源条数和表达习惯，可进入两端聊天原文。电脑离线或断开后仍可查看；模型密钥、截图图片和未发送草稿不上传。

电脑编辑时保持开始编辑的资料版本。手机产生新版本后保留电脑未保存修改，保存时进入版本比较，避免直接覆盖手机内容。

构建、验收和真实手机限制见 [第三批交付报告](../../docs/reports/android-link-ux-2026-10-09.md)。
