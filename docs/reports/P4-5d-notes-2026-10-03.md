## 本轮新增：列访问族内部的结构性联系

`0x3a24620`（列访问族中唯一的单参成员）是一个薄包装，反汇编全文如下：

```text
03a24620  48 89 5c 24 08        mov [rsp+8], rbx
03a24625  57                    push rdi
03a24626  48 83 ec 20           sub rsp, 0x20
03a2462a  48 8b f9              mov rdi, rcx           ; pStmt
03a2462d  e8 2e fa ff ff        call 0x3a24060         ; 边界检查（magic + iCol）
03a24632  8b d8                 mov ebx, eax           ; 保存状态码
03a24634  85 c0                 test eax, eax
03a24636  75 14                 jne 0x3a2464c          ; 失败直接返回状态码
03a24638  48 8b 0f              mov rcx, qword ptr [rdi]      ; pStmt->pVdbe
03a2463b  48 8b 49 18           mov rcx, qword ptr [rcx+0x18]
03a2463f  48 85 c9              test rcx, rcx
03a24642  74 08                 je 0x3a2464c
03a24644  ff 15 96 f3 cb 01     call qword ptr [rip+0x1cbf396] ; ->0x56e39e0（IAT 槽）
03a2464a  8b c3                 mov eax, ebx           ; 返回值是该状态码，不是被调用者的返回值
03a2464c  ... 恢复并 ret
```

**两点可复核的事实**：

1. 它**丢弃了间接调用的返回值**，最终返回的是边界检查的状态码——即"调用一个带副作用的例程并汇报成功/失败"，不是取值函数。
2. `0x56e39e0` 这个函数指针槽**在 `0x3a24220` 的尾部（`0x3a242f2`）同样被调用**。两个列访问族成员共用同一个 IAT 目标，这是家族内部的结构联系，可作为后续交叉验证的锚点。

## 本轮结论：身份判定遇到外部依赖，已到本机能力边界

要把这 8 个宿主逐个对应到 `sqlite3_column_name`/`column_type`/`column_blob`/`column_bytes`/`column_value` 等具体名字，需要 **SQLite 3.28.0 的一手源码**（amalgamation）做函数体比对。本轮核实：

| 途径 | 结果 |
| --- | --- |
| 本机全盘搜 `sqlite3.c` | 不存在 |
| 本机 `sqlite3.h` | 只有 Anaconda 的 **3.24.0**（早于 3.28.0，不可用） |
| 本机 Python 的 SQLite | **3.45.3**（同样不可用） |
| 联网取 `sqlite3.h` | 取到的是 **3.50.1**（不可用） |
| `raw.githubusercontent.com` 的 SQLCipher v4.2.0 | 抓取失败（`fetch failed`） |

因此本轮**不给任何函数名结论**。这不是"再挖一挖就能出来"的问题，而是缺一份可比对的基准材料。

## 未决项（需要外部输入）

1. **SQLite 3.28.0 的 `sqlite3.c`**（SQLCipher 4.2.0 打包的那一份）。有了它就能把 8 个宿主逐个定名，也能顺带求出 `prepare`/`step`/`finalize` 的真实入口。
2. 若不便提供源码，替代方案是**允许联网抓取**（GitHub 当前不可达，可能需要可用的镜像或代理）。

## 仍然成立的结论（未因本轮改变）

- 内嵌引擎为 **SQLCipher 4.2.0 / SQLite 3.28.0**（三条证据互证）。
- 登记的 10 个 `k_sqlite3_*` 偏移**不是函数入口**（9 个落在异常目录范围内部、9 个无序言字节、`exec` 落在一条 7 字节指令的 disp32 中间、`exec` 直接调用点为 0）。
- `0x3a6d90` 与 `0x3a64b0` 是**经调用点反推并经结构验证**的活入口（64 / 104 个调用点）。
- `disposition` 保持 `NO_GO`，`voiceDatabaseReady=false` 不变；MediaMSG/BufInfoStorage 归属**仍为零证据**。
