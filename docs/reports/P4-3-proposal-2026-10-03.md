# P4-3 真实图片/语音 provider 与独立限额 范围审定

2026-10-03，按 [开发计划 §4](development-plan.md) P4 默认顺序，P4-2 之后的下一张卡。模块 04，协作 01/07。本页为提案，**审定前不改动任何源码**。

## 为什么是这张卡

P4-1 交付了 `BinaryMediaProvider` 端口与合成夹具，P4-2 交付了解释持久化、快照版本引用与同步失效复核，但两者都明确写着「没有默认真实 provider」。开发计划里多媒体剩余项依次是：真实 provider 与独立限额 → 微信原文件获取与真机验收 → 网页纠正入口。本卡只做第一项，且**只做离线可验证的部分**：真实平台的字节获取与本人在场的付费调用分别属于后两张卡与本人。

## 事实依据（2026-10-03 核对官方文档）

- [`deepseek-flash` 已支持图像输入](https://api-docs.deepseek.com/zh-cn/guides/vision)：OpenAI 兼容 `content` 块数组 + `image_url`（base64 data URL / 外链 / Files API），格式 JPEG/PNG/GIF/WebP，**按文件实际内容判断而不看声明的 MIME**；单图上限 32 MiB（内联）、缩放后每图最多 1024 token、按 V4-Flash 同价计费；图片只能出现在 `user` 消息里。旧的 `deepseek-v4-flash-vision-exp` 已下线，请求由最新 Flash 模型承接。
- DeepSeek 官方文档**没有语音转写/音频输入**能力（[更新日志](https://api-docs.deepseek.com/updates/)与 API 指南均无 ASR 条目；搜到的「1MB 音频限制」来自第三方 issue，不是官方文档）。因此本卡**不臆造语音能力**：语音 provider 走通用 OpenAI 兼容 multipart `/audio/transcriptions` 适配器，未显式配置时语音支持列表为空，语音继续 `UNSUPPORTED_CAPABILITY` 转人工。

## 要做什么

1. **图片真实 provider**（OpenAI 兼容 chat completions + base64 data URL）。只接收 04 已校验的单个媒体字节与 codec；强制 base64 长度上限、请求体上限、`detail` 仅允许文档列出的取值；图片格式白名单为官方文档的四种，且**在本地按文件头复核**，声明与内容不符则拒绝而非硬塞。
2. **语音转写 provider**（OpenAI 兼容 multipart `/audio/transcriptions`）。列出明确的接受格式，未配置即不支持；同样只接收单个媒体。
3. **两者都返回 04 现有 `BinaryMediaProvider` 形状**，并返回与文档一致的结构化解释：非空正文、`completeness`、图片 `visualCoverage=full_image` 或语音 `transcriptCoverage=complete`、不确定性、`criticalUnclear`。模型自报覆盖仍不等于质量通过。
4. **写死 prompt 版本常量**，与 `prompt-versions.mts` 的版本化约定一致；provider 通过现有通道声明 `promptVersion/modelVersion/dataRegion/retentionPolicy`。
5. **独立限额**（开发计划明确要求）：媒体调用与 token 限额**独立于**文本限额，并按图片/语音分别计数，超出拒绝（`MODEL_BUDGET_EXHAUSTED` → 04 映射 `MODEL_UNAVAILABLE` → 02 转人工）。同样是进程内失控闸，不是月预算；D06 未定，默认值取保守值并在文档标注待本人确认。
6. **显式装配开关**：`MEDIA_VISION_ENABLED` / `MEDIA_VOICE_ENABLED` 默认关闭；关闭时工厂拒绝创建，绝不静默使用真实模型。装配只落在 `apps/core/config.mts` 的配置校验（**当前核心组合根没有媒体路径**，所以这只是配置面，不改运行行为），媒体进信路径保持现状：没有原文件仍转人工。
7. **离线验收**：本地假 HTTP 服务（临时自签证书 + 注入 `fetchImpl`）驱动真实适配器代码，覆盖请求形状、格式复核、限流、超时、畸形响应、限额与泄漏边界（日志/错误不含正文、路径、密钥、身份）。**不调用真实 DeepSeek**。

## 验收

- 新增离线单测全绿，完整门禁 0 fail、0 skip（真实 PostgreSQL + 浏览器 E2E）。
- 负测：未开启开关即拒绝创建；图片格式/大小/空字节/超限拒绝；语音未配置即不支持；文本限额耗尽不影响媒体限额，图片限额耗尽不影响语音；超时与畸形响应映射为结构化失败，不产生可发送候选。
- 报告分栏写清「离线适配器验证」与「真实模型未验证」，不改写 P4-1/P4-2 的结论。

## 边界（不做）

- 不调用真实模型、不产生费用、不写真实密钥进仓库；真实付费调用需本人在场单独授权（红线）。
- 不取微信原文件、不改桥接与平台入口、不改公共 wire 类型/状态/事件、不新增迁移或依赖（0013 仍未分配）。
- 不装配生产媒体派发；不因本卡放开 AC06/AC07，也不开启 P3 自动模式。
- 语音 provider 不猜测供应商；本卡只提供通用适配器与「未配置即不支持」的失败关闭。
