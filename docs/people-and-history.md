# 同一个人的多个聊天来源

本轮源码版本：电脑 2.2.0，Android 0.9.0 / code 23。人物关联、导入与检索使用迁移 0019；旧账号、联系人、原始消息和发送路径保留。

## 电脑如何使用

打开工作台「人物与导入」。现有联系人各自形成独立人物，不因昵称相同合并。

1. 选择人物，或新建一个人物。
2. 将另一个现有聊天渠道明确关联到这个人物。另一个平台/账号只有历史文件时，展开「新增另一平台或账号的历史渠道」，填写平台、我的账号标识和对方标识。这种渠道仅保存历史，不登记平台收发会话。
3. 选择导入渠道，再选择文件。先核对预览中的原文、说话人、原始时间和重复项，再确认导入。取消预览不会写入消息。
4. 人物记录可以查看全部渠道或单个渠道、翻页；导入记录保留文件名与行号。已导入的文字可以纠正或删除。手机上行原文通过手机或「手机联动」的既有纠错入口处理，避免绕过双端冲突规则。
5. 可靠原文可以点击「整理为长期记忆」，选择所属人、记忆类型和到期时间，由本人确认。含不确定标记、未知说话人或 AI 生成内容不能直接形成确认事实。

“人物”对应一个真实的人；“渠道”对应平台、本人账号和对方聊天；“导入批次”对应一次文件或截图获取。同一渠道的多次文件导入不会新增人物或渠道。

## 文件格式

已支持 JSON、CSV、TSV 的统一格式；页面可下载 JSON 模板。QQ 原有 NapCat 历史读取导入继续可用。平台专有导出文件仍需要对应格式解析器，不能把任意微信数据库、HTML 或备份文件当成已支持格式。

JSON 可以是消息数组，或 `{ "messages": [...] }`。CSV/TSV 首行是字段名；支持引号、引号转义和多行文本。

|字段|填写方式|
|---|---|
|speaker|`ME` 本人、`OTHER` 对方、`UNKNOWN` 说话人未知；不用昵称猜身份|
|text|原文|
|timestamp|带时区的 ISO 时间，例如 `2026-10-13T10:00:00+08:00`；未知则 JSON 用 null，CSV/TSV 留空|
|messageId|可选；真实原消息 ID，不能填写所有消息共用的占位编号|
|uncertain|可选 true/false，表示内容或说话人待核对；时间未知另外保存，不伪造聊天时间|

单次文件不超过 2MB、5000 条。不同来源有不同字段时先整理成以上格式，保留原文件用于核对。导入不调用模型、不创建实时回复或发送任务。

## 重复记录与身份

- 消息 ID 在同一渠道内去重，也检查已接收的实时消息；ID 相同而原文、说话人或时间冲突时拒绝覆盖。不同渠道即使 ID 或文字相同，也独立保留。
- 相同文件的无 ID 行通过文件摘要与行号防止重复导入。不同文件的相似原文只列为疑似重复，默认保留；本人选择同一条后才引用已有记录。
- 每条 canonical 消息可以关联多个导入批次；文件名、行号、原始时间/说话人标记保留在批次记录中。确认导入后清除暂存预览正文。
- 关联、解除、改渠道名称或关闭共同参考有版本检查，过时预览不能提交到已经变更的人物。解除关联只改变人物关系，原消息仍在原渠道。

## 手机如何使用

覆盖安装 0.9.0，保留本机档案和配置。聊天档案仍对应具体渠道，截图时先选择正确的渠道，再识别、核对和保存；现有截图重叠处理仍只作用于该渠道。

聊天记录页面新增「全部渠道 / 仅当前渠道」和「人物与渠道」。纯本机档案可以明确关联或解除，原记录不搬动。已连接电脑的档案由工作台管理人物关系，再同步；手机联动页显示电脑下发的渠道列表，电脑目录也提供新增的历史渠道供配对后关联。

同一人物的跨渠道原文和有效记忆在同步后下载。电脑离线时使用上次下载的缓存；离线期间发生的电脑纠错、删除或解除关联，要重连同步后才能获知。备份恢复或主动断开后，停用的电脑关联不能继续给生成提供跨渠道背景。

## 回复如何共同参考

电脑 v2 生成和手机独立生成优先使用当前渠道的近期对话与当前触发批次；其他渠道只提供有出处的相关背景与有效记忆，不混入当前来信，不改变回复目标。共享背景先让出上下文预算，明确边界和锁定记忆保留。

不同渠道的信息矛盾时保留出处，提示模型不要擅自选为事实。共同参考可以按渠道关闭。来源修订/删除、记忆失效或人物关联变化都会阻断旧上下文继续用于审批或复制；手机本机其他渠道的改动也会使旧候选失效。

## 升级与回退

这份交付包含源码、网页构建及 APK；本轮没有替换真实运行服务或迁移真实聊天库。运行服务需要按现有方式备份数据库及配置，再执行迁移/管理式更新；手机需要覆盖安装新 APK。回退源码时保留新增表及原账本，不删除历史，不恢复已失效候选。手机在同步请求中声明 `personChannels=true` 后才下发跨渠道资料；旧手机仍只接收当前渠道，降级时跨渠道缓存记录下发删除标记，避免旧流程混入其他渠道。完整使用需要手机升级。

老双平台入口如果使用两个独立数据库，人物关联以各自数据库为边界；本轮跨平台能力用于同一 v2 数据库中的渠道。没有默默查询另一个运行目录的私有数据库。
