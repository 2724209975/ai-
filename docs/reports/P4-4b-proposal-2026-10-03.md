# P4-4b 图片完整性验证范围审定

本人要求完成下一环节，总控按开发计划 P4-4b 审定本卡。现有文件头识别不能证明图片下载完整；仅添加末尾标记同样不能证明压缩像素有效。

采用成熟的 sharp/libvips 解码器，在独立子进程中完整解码像素，不缩放、不转码、不将解码后像素写入聊天存储。父进程限制输入字节、并发和时限，子进程限制像素数与通道数；取消/超时终止子进程。只接受 PNG/JPEG/单帧 GIF/单帧 WebP，动画、BMP 和无法证明完整的内容转人工。PNG 动画扩展额外显式拒绝，防止首帧误当完整画面。

总控批准根 `package.json` 与锁文件新增并精确锁定 sharp（版本以安装时 npm 官方发布元数据为准），不新增数据库迁移。新依赖属于本卡功能实现，并不启用任何真实模型或平台能力。

可改：`packages/data/media/` 的共享图片验证器/子进程/限量读取及测试；`packages/platform/wechat/media-acquisition*`；`packages/ai/understanding/vision-provider.mts` 及媒体 provider 测试；合成图片夹具、PG 图片集成测试、解码模块无发送能力的架构守护；根依赖清单；模块 README、runbook、开发计划及本卡报告。共享验证器由 01 获取和 04 发送模型请求前共同使用，不包含发送平台或付费模型能力。

验证先写复现：仅文件头、截断/损坏像素、分段写入、读取期间变大、像素/字节超限、取消/超时、动画拒绝；模型端对失败输入零请求；完整合法图片的 SHA-256 与字节保持不变。完整门禁 0 fail / 0 skip，真实平台仍由本人专项验收。

官方依据（2026-10-03 查阅）：[sharp 输入选项](https://sharp.pixelplumbing.com/api-constructor/) 提供严格失败与像素限制，[安全说明](https://sharp.pixelplumbing.com/security/) 建议对不可信输入保持严格解码并限制资源。本卡不承诺操作系统级内存沙箱；进程隔离、输入/像素/并发/超时限制均需实际负测。
