# P6 离线验收、对比与灰度回滚

本轮执行用户选择的“先完成离线验收和灰度演练”。真实聊天回放、付费云端测试、真人盲测和实际联系人上线分别保留待验项，不能由合成测试替代。自动发送授权始终为false。

## 可重复执行

```powershell
# 不需要模型、平台或数据库：160组中文合成场景，v1/v2同一截止点对比
npm run eval:p6

# 先配置独立测试库的 TEST_DATABASE_URL，再运行真实PostgreSQL验收
# 测试自行创建随机schema，不使用日常运行库；缺少URL会失败，不会静默跳过
npm run test:p6

# 整个项目验收：集成库、备份客户端、pgvector和浏览器须已准备
npm run verify
```

内置样本为`tests/fixtures/p6/chinese-scenarios-v2.json`，160个不同中文输入，8类各20例：日常、试探、升温、冲突、边界、跨周、缺失事实、提示注入。明确标注synthetic，externalModelAuthorized=false；不是来自真实用户聊天。沿用原`prepareReplaySamples`隐私/授权格式、消息截止过滤和版本化事实过滤，不扩宽其50样本限制；逐场景复用同一验证器。私有账号标识/电话/邮箱等、未知字段和重复ID拒绝。

`eval:p6`输出`output/p6/replay.json`及带独立时间戳的盲测题包/答案键。数值报告保留数据集hash、场景分类、两个流程的决策/风险、质量门禁、截止后排除数量、处理延迟和失败原因。此命令没有数据库/网络/平台端口。CLI错误退出非0。

`test:p6`执行P1/P2/P3/P4/P5/P6相关集成和验收单元；清除继承的真实模型、平台、Owner和默认数据库配置。显式TEST_DATABASE_URL只允许本机数据库；开发者仍须选择独立测试库。输出`output/p6/postgres-acceptance.json`，实际走现有PgConfirmedService、迁移、任务状态机、上下文、审批/账本及Mock平台。普通`npm run verify`也包含本轮新增测试；CI另执行离线回放。

## 指标和性能

- Recall@5按期望记忆ID与检索前5个ID计算，不使用模型自评。20个跨周主题，每主题原问/改述2个标签，额外20个有效且有来源的干扰记忆；共40个查询。真实PostgreSQL检索，而非测试中手工排序。
- 明确边界20例使用无相同关键词的查询，仍须全部返回；低重要性不允许漏掉。另测来源版本改变、对方隔离；原P2/P3测试继续覆盖删除/纠正/过期/向量/缓存/多账号边界。
- 计量覆盖按实际注入Provider调用数与数据库脱敏账本行数计算，成功和失败都计入。用量未知、价格未知与“未记账”是不同情况，不能用零费用掩盖未知。
- 安全失败涵盖供应商错误、显式备用模型、非法决策和质量阻断；原P4专项继续覆盖超时、预算、配置失效和迟到输出。
- P50/P95记录整段接入到候选/停止的耗时和记忆检索耗时。这里使用本机数据库和进程内Provider，不含真实模型网络等待；不能外推线上SLA。

本轮实际修复通用“之前聊过”词组和时效挤掉明确记忆内容的问题。排序在已授权且来源有效条目中增加`exact_memory_object`权重：语义0.35、关键词0.25、问题明确提到的记忆object 0.20、时效0.10、可信度0.05、重要性0.05。至少2字符且采用NFKC/空白归一化。边界/锁定/重要承诺的强制排序与token超预算拒绝不变。

证据校验由每条记忆逐来源查询改为一次批量版本/账号/会话/归属/真实消息查询。40个记忆的检索实际固定10次SQL，含权限绑定和读取；一条来源版本改变即移除引用旧版本的条目。没有缓存失效或范围检查的豁免。

模型用量新增近30天`models`聚合，按task/provider/model/modelVersion/promptVersion/币种区分；不会从“最近100条调用”推算全部用量。控制台显示每模型次数、错误、实际token、用量已知次数、P95、已知费用和未知费用次数。没有新增推测价格、默认模型或发送权限。

## 盲测工具

题包仅含截止点内的输入和A/B正文，模型ID、策略标签、版本和答案键独立存放；A/B随机排列，hash绑定题目。不要把答案键给评审者。输入是真实数据时题包是私有材料，不提交Git或公开报告。

评分文件是JSON数组，例如：

```json
[{"sampleId":"daily-01","reviewerId":"reviewer1","choice":"A"}]
```

choice为A/B/tie/neither。同一评审者/同一题只能评分一次，未知题号和非法选择拒绝。不提供默认评分。运行：

```powershell
npm run score:p6 -- <题包路径> <答案键路径> <人工评分JSON路径>
```

当前v1/v2本地fixture正文相同，题包只验证评审流程，不能证明任一模型更自然。未来真实模型比较须使用相同截止上下文、不同真实Provider/模型或提示版本，并另行授权数据范围、总调用/token/费用上限。候选采纳率、修改率、真人偏好、网络耗时和真实费用继续使用实际反馈/模型账本，不制造人工结果。

## 按会话灰度与回滚

测试中只让合成A会话切换v2；B保持v1。连续验证未授权不发送、回滚幂等、旧审批拒绝、生成中回滚、重启恢复、历史/记忆/模型调用账本保留，以及UNCERTAIN不重发。本轮没有真实联系人灰度上线。

未来真实试点需本人逐联系人授权；先确认聊天设置为人工审批，再用已有Owner接口`POST /api/v2/conversations/:id/pipeline`启用version=2。body带当前conversationVersion和新idempotencyKey。查询/上下文预览不授权发送。收到新来信后查看诊断与上下文，编辑并明确审批最终文字，在原客户端核对实际送达。

遇到泄露、错误事实、重复/旧任务、未知发送或异常费用，暂停该联系人；停止新审批，核对已提交/未知发送，再以同一接口version=1回退。回退使未提交候选/任务过期，保留已提交、送达、未知结果与send_key，不撤销已发生的平台调用。UNKNOWN_SEND须原平台对账，不能通过切换/重启/新来信消除。

不删除0015–0017迁移。结构是增量兼容的，优先做业务管线回退；恢复整库前须备份当前账本并核对外部发送状态，防止恢复旧备份后重复发送。独立集群启动/恢复及备份客户端回归仍由已有集成测试覆盖。

## 上线判定

`acceptanceGate`要求150+场景、泄露/重复/旧候选/未授权高风险发送为0、Recall@5≥90%、边界100%、计量覆盖≥99%、安全失败100%、回滚通过。空分母返回未知并拒绝通过，不能当作100%。

合成数据通过这些门槛时只得到offlinePassed=true。releaseReady仍要求脱敏真实回放、真实模型评估、真人盲测和逐联系人授权；缺项列入pending。该函数仅评估报告，没有部署或发送权限，automaticSendAuthorized恒false。本轮交付见[P6报告](reports/v2-p6-2026-10-11.md)。
