## P01：本人账号发出的消息，来源证据不足时的公共事件

### 动机与触发

QQ OneBot `message_sent` 等自身消息信号只说明消息由账号发出，不能证明是本人在原客户端操作，还是系统发送后的平台回显。01 可以用持久发送账本的精确 `(平台, 账号, 联系人, 平台消息 ID)` 关联系统回显；无关联且无经真实账号验证的独立设备来源信号时，必须保留 `actor=unknown`。当前六类公共事件只有 `PlatformOwnerMessageObserved` 和 `PlatformAgentEchoObserved`，若把 unknown 自身消息塞进普通 `PlatformInboundObserved`，02/03 可能把它误当联系人入站而触发回复。

### 建议变更

增加 `PlatformSelfMessageUnattributed` 事件，载荷复用标准 Message 的平台/账号/会话/联系人/平台消息 ID/时间/内容或媒体引用/原事件引用，另有 `originStatus=unknown` 和去重键。02 收到后暂停该联系人自动发送、失效尚未提交任务并请求人工核对；03 保存消息但不将其作为本人风格事实或系统回显。后续若获得经审计的精确证据，由新的 `PlatformMessageOriginResolved` 事件引用原事件和证据版本，更正为 `owner` 或 `agent`，不得悄悄覆写原始来源。是否用这两个名称、是否复用现有 `PlatformMessageMutationObserved` 承载更正，由 00 确定。

### 兼容、迁移与回滚

这是新增事件种类而非对现有事件静默改义。00 若接受，需先发布新 schema/version 和消费者；01 再开始发布。旧消费者若不识别新事件，应拒绝自动处理并将账号/联系人保持暂停，不能回退成 `PlatformInboundObserved`。已有来源未明的历史消息按原证据重评，不按文本/时间猜测；迁移只标记未知并留下可核对引用。回滚到旧消费者时保持发送暂停，不转换为 owner 或 contact。

### AC 与协作者

- AC05：与原事件相同的去重/顺序语义；更正事件有独立事件 ID、因果引用。
- AC16：未经验证不触发“本人接管已确认”；但暂停自动处理以防误发。确认 owner 后触发接管、失效旧计划。
- AC18/AC20：发送回包丢失或提交状态未知时，自身消息不能被当 owner 来解除发送未知阻塞，也不能重复发送。
- 00：定事件名、schema 与兼容门槛；02：暂停/恢复语义；03：来源版本、存储及更正；06：展示“来源待核对”；07：跨模块合同与恢复测试。01 提供原始事件索引、账本关联证据和保守分类。

当前 `packages/platform/qq/self-origin.mts` 只是 01 内部分类端口，owner verifier 无真实实现；模拟测试不证明目标 QQ/微信具备独立来源信号。

## P02：恢复报告明确历史覆盖和发送未知

### 动机与触发

公共 `reconcile(accountId,sinceCursor)` 尚未定义结果字段。桥接恢复在线并不等于断线期间的消息补齐。NapCat 维护者[列出 `get_friend_msg_history`](https://napneko.github.io/develop/api)，但该列表未证明能从本项目持久 cursor 连续、无漏地恢复。提交中断后，若只凭重新连接或未核实的历史窗口清除 `RESULT_UNKNOWN`，会产生旧回复或重复发送风险。

### 建议变更

由 00 定义版本化 `RecoveryReport`，至少包含：账号和桥接会话身份、持久前游标、被验证覆盖的起止范围/覆盖等级、最新可持久游标、历史缺口、预提交旧任务 ID、按账号/会话/sendKey 绑定的未决发送证据状态与平台消息 ID、待人工核对的会话。`historyComplete` 必须有来源能力与实测依据；仅“请求历史 API 成功”不能写 true。02 收到报告后先作失效与当前版本 preflight；01 不自行重发或恢复旧任务。某个会话的未知发送只阻塞该会话，账号连接或历史缺口则按影响范围拦截。

### 兼容、迁移与回滚

可以先以可选字段扩展恢复结果，但旧消费者看不到覆盖/未知证据时必须按 `historyComplete=false`、发送未知处理。若 00 认为新字段必填，升级事件版本并双读迁移。旧游标无法映射新桥接版本时保留旧值及缺口，不能静默推进到最新。回滚时暂停自动发送，不回放预提交回复。

### AC 与协作者

- AC05：历史补齐事件仍按持久平台键去重，乱序不丢证据。
- AC17/AC18：旧任务失效、提交未知核对、晚到回包单调更新，不自动补发。
- AC19：发送未知按会话隔离；账号级历史缺口另行标识。
- AC23：关机恢复验证报告必须记录真实覆盖范围，不能以客户端重连代替。
- 00 定 schema；02 定重新 preflight/会话阻塞；03 定游标、账本与原事件事务；07 做断线和进程重启实测。01 提供桥接能力证据与报告。

当前 `packages/platform/qq/recovery-assessment.mts` 只计算保守离线结果，不连接平台、不持久化游标，也没有证实 NapCat 历史覆盖能力。
