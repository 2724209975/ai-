## 建议配置（2026-09-23，待 07 按 D06 容量/预算确认）

若新建测试实例或确认现有实例可调整，选阿里云 ECS **Ubuntu 24.04 LTS 64 位 x86_64** 公共镜像、**4 vCPU / 8 GiB RAM**、**100 GiB ESSD 云盘**，无需 GPU。核心 API、worker、PostgreSQL 17、私有媒体卷和 QQ 候选桥接先在同一宿主的隔离容器/私有网络中验证。4/8/100 是本项目的保守测试预算，**不是组件官方最低规格、生产容量结论或采购决定**；`docs/architecture.md` 中 2 vCPU/4 GiB 仅是未运行桥接/本地模型的测试起点。费用和容量需 07 按实际区域、媒体量、备份、模型调用测算。现有实例若满足要求，优先只读核查后复用；不为匹配建议而直接重装系统。

公网入口仅预留经 07 配置的 HTTPS 443；SSH 22 只允许本人固定来源 IP/VPN。OneBot HTTP/WS、NapCat WebUI、PostgreSQL 与媒体卷均不直接暴露公网；具体反向代理、TLS、备份与监控归 07。平台登录状态和认证令牌使用服务器私有持久存储，不写仓库或普通日志。QQ 桥接以固定版本及镜像摘要进行专项验证，在验证前不运行安装脚本或登录本人账号。

这台 Linux ECS 可以承载核心与 QQ 候选桥接，**不能据此认定微信个人账号已接入**。若微信最终选用 Windows 客户端桥，另需独立常在线 Windows 主机/虚机和桥到核心的安全连接；当前微信路线尚无通过验证的候选。开本人电脑关机后微信和 QQ 各自真实收发，仍是两项独立的 AC23 实测。

配置依据：阿里云 [Ubuntu 24.04 x64 公共镜像](https://help.aliyun.com/zh/ecs/ubuntu-image)，Docker [Ubuntu 24.04 安装支持](https://docs.docker.com/engine/install/ubuntu/)，NapCat 维护者的 [Linux Docker 启动说明](https://napneko.github.io/guide/boot/Shell)。NapCat 文档是候选组件声明，不是本项目实测。阿里云 [更换系统盘说明](https://help.aliyun.com/en/ecs/user-guide/replace-the-operating-system-of-an-instance-1)指出更换系统盘会删掉原盘数据并中断服务，故现有实例有数据/业务时先核查，不直接换镜像。

## 当前需要的信息

请先确认现有实例是否运行需保留的业务、有无重要数据。然后本人或运维在服务器执行以下**只读**命令并提供输出；不需要密码、密钥、登录二维码、IP 地址、账号名或聊天记录。可删去输出中的主机名、用户名和公网 IP。

```sh
cat /etc/os-release | grep -E '^(NAME|VERSION|VERSION_ID)='
uname -m
nproc
free -h
df -h / /var/lib/docker 2>/dev/null || df -h /
docker --version 2>/dev/null || true
docker compose version 2>/dev/null || true
```

这些输出只确认系统、架构、资源与 Docker 状态；已有业务需由本人另行说明，不能从输出缺失推断为空机。

1. 只读核查架构/系统、现有容器或客户端、磁盘空间及已有业务占用。不改现有防火墙和安全组，不开放公网机器人接口。
2. 依据实际环境固定候选客户端与桥接版本，核对官方/维护者支持、许可和下载来源。QQ 的 OneBot 协议层可以复用；桥接本体仍需选择。微信目前没有已验证路径，不在服务器上试装多个未知客户端。
3. 给出具体安装目录、资源预算、监听范围、凭据位置、所需权限、卸载/撤销方法及对已有业务的影响，再由本人完成必要授权/配合。不得执行不经审查的一键安装脚本。
4. 使用独立测试会话，先接收与来源/媒体验证，再在 verification.md 的批准清单内发送。不因服务器存在就自行登录主账号或联系好友。
5. 核心与桥接均位于独立在线端后，再关本人日常电脑进行微信/QQ 分开的 AC23 测试。需要手机客户端扫码或在线的情况如实记录。

服务器上的未来持久数据：登录会话秘密、平台事件去重记录、发送账本、同步位置、原媒体。秘密不能写仓库/普通日志；事件与媒体遵循 03 私有存储。跨机器的媒体 file:// 路径不能直接假定可读，需明确桥与媒体存储的共享/传输方式。
