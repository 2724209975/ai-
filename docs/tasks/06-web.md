# 任务 06：手机网页管理端

## 任务目标

实现单用户、手机优先的管理端：总览/连接与故障、联系人策略、会话、候选确认、暂停/恢复、资料/记忆、媒体与识别纠正、分析证据、表情素材、历史导入、Skill 管理/试用、审计。UI 只呈现并提交后端权限，不复制权限判定。

## 必读与范围

依次读 PRD v1.3 §4–5、§7–10、§13–16，[架构](../architecture.md)、[公共契约](../contracts.md)、[决策](../decisions.md)、[计划](../development-plan.md)。主要协作几乎全部 AC，重点负责 AC03、AC15、AC20、AC27、AC31–32、AC35、AC37 的 UI 证据；AC 的业务主责仍按 development-plan。

负责 `apps/web` 和管理 REST adapter/查询层；如 `apps/api` 为共享装配点，仅提交明确路由模块。不得直接访问数据库、PlatformPort 或 ModelGateway，不在前端根据置信度/按钮状态自行放行。

## 输入输出与依赖

消费 `/api/v1` 查询中的 version、status、reason、allowedActions、correlationId；写操作调用 Orchestration/Data/Skill 的 owner 命令并携带 expectedVersion/idempotencyKey。409 STALE_PLAN/CONFLICT_VERSION 必须刷新并清楚显示旧内容未发送。

依赖 02 提供状态/命令、03 提供受控媒体与证据查询、05 提供 Skill 管理，01 连接状态，07 登录/HTTPS。D02 未定前只承诺网页内待办和轮询；D03 未定按“发送”和“恢复”分开的安全 UX。

## 实施要求

首条竖切：总览→联系人→会话/候选 1–3 个（每个多条）→编辑→确认→提交状态/回执。必须显著区分未发送、提交中、已发送、失败、结果未知、部分发送、过期；不把平台接受画成对方已读。全局/联系人暂停明显且二次提交可幂等。

分析展示数据截止、范围、证据/反证据/替代解释/不确定性和版本；纠正/删源后显示重算或失效。Skill 显示版本、启用范围、临时指定、调用原因；试用显著标“不发送”。可以自行决定组件库、路由、移动端布局、可访问性实现；不得把产品待定参数固化为不可配置值、暴露原始存储 URL/凭据、允许对方消息触发管理动作或声称网页轮询是后台通知。

## 验收与交付

- 真实手机视口覆盖窄屏、触控、慢网、重复点击、刷新/返回、会话过期；核心控制可键盘操作并有明确焦点/错误。
- E2E 覆盖旧确认 409、新消息更新、编辑多条、结果未知、部分发送、单人/全局暂停、其他联系人不受影响。
- 后端撤掉 allowedAction 或版本变化时，即使伪造请求也不发送；前端无业务授权常量副本。
- 私有媒体通过短期鉴权端点加载，日志和错误不泄露内容/令牌。
- 交付记录列页面/路由、API 依赖、手机测试矩阵、截图/AC 证据、D02/D03 限制、公共变更提案。
