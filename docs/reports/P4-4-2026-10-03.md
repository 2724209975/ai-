# P4-4 微信原文件获取（图片链路打通，语音留卡）

2026-10-03 开工并当日完成离线开发，分支沿用 `task/P4-2-media-persistence`。范围按本人选定的方案 1（收信时同步取原文件、事务内登记）。本卡**没有启动微信、没有注入或调用真实 helper、没有发送、没有产生费用**，也没有新增迁移或依赖（0013 仍未分配）。

## 结论先行

- **图片**：链路已打通到可离线验证的程度——桥接取值、按字节解容器、私有落盘、与消息同事务绑定，`buildContext` 投影里第一次出现真实 `mediaId`。
- **语音**：经查**在本固定 helper 构建上不可能取得**。部署的 DLL 来自 `dev-3.9.11.25`，其 `GetVoiceByDB` 是空壳 `return 0`，另一份源码树（3.9.8.25）同样是空壳，没有上游实现可移植；因此 `/api/getVoiceByMsgId` 一次都不会被调用。语音获取单独立卡（P4-5）。

## 交付

### 01：只读取值传输（新增 `packages/platform/wechat/wxhelper-media-transport.mts`）

- `WxhelperLoopbackMediaTransport` 只发一个 `POST api/downloadAttach`，body 是 `{"msgId":<十进制字面量>}`。边界要求 http + `127.0.0.1`/`::1` + 无凭据/查询/片段，端口任意（默认 `http://127.0.0.1:19088/`）。
- 响应必须是 `200` + JSON + 有 body 且不超 16 KiB，`code` 必须是数字；**非零只表示「受理」，不表示文件已写出**。
- 错误只用固定名（`PLATFORM_UNAVAILABLE`、`WX_MEDIA_HTTP_<status>`、`WX_MEDIA_MSGID_UNSAFE`），文本里不含 msgId、路径或响应正文。

### 01：容器解码（新增 `packages/platform/wechat/media-dat.mts`）

- 复刻 helper `DecodeImage` 的整段单字节 XOR：由首字节与 JPEG/PNG/GIF/BMP 候选头推出密钥，整文件解混淆。
- **比 helper 多一步**：解混淆后再校验容器头确实匹配，否则返回 `undefined`。XOR 判定只比较两个字节，非图片可能偶然通过，那样会以「图片」名义存进 03。
- 只支持 helper 认得的四种容器；**WebP 明确不支持**（helper 的 `DecodeImage` 也不支持）。

### 01：获取编排（新增 `packages/platform/wechat/media-acquisition.mts`）

- 只处理 `kind='incoming' && type='image'`；`voice` → `VOICE_UNSUPPORTED_BY_HELPER`（**零请求**），其它类型 → `NOT_MEDIA`。
- 路径由 `WECHAT_DATA_PATH` 与 helper 固定布局推出：`<dataPath>\wxhelper\image\<msgId>.dat`；相对路径、`..`、非数字或超 16 位 ID 一律 `PATH_INVALID`。
- 流程：`downloadAttach` → 轮询文件出现（默认 250 ms / 8 s）→ 先 `stat` 比 10 MiB 上限 → 读文件 → 解容器 → SHA-256。
- 失败原因固定：`TRANSPORT_FAILED`、`HELPER_REJECTED`、`FILE_NOT_WRITTEN`、`FILE_TOO_LARGE`、`DECODE_FAILED`、`PATH_INVALID`、`VOICE_UNSUPPORTED_BY_HELPER`、`NOT_MEDIA`、`DISABLED`。任何失败都只降级为转人工，**不重试**。

### 03：登记接口（`packages/data/postgres/provider.mts`）

- 新增 `attachMediaToMessage(tx, { callerContactId, contactId, messageId, expectedMessageVersion, asset })`：委派既有 `PgMediaRepository.register` 建资产行，再补一条 `UPDATE data_messages SET media_id=…, version=version+1 WHERE … AND media_id IS NULL`。
- 与插入消息同事务；重放同一平台消息是幂等的（资产已存在则不覆盖 `media_id`）。
- **不额外抬高 epoch、不写第二个 `EvidenceInvalidated`**：同一事务里的消息插入已经做过，且瞬刻之前不存在的资产不可能被快照引用——这一取舍写在方法注释与 03 README 里。
- `reception.commitReceived(rawBytes, observation, media?)` 新增可选第三参数（值，不是回调），outbox 事件在事务内构造、提交后才派发，因此重放不会重复发布事件。

### 07：桥接装配（`apps/bridge/wechat-bridge.mts`、`wechat-main.mts`）

- 顺序为：**先落库消息 → 再取字节并私有落盘 → 第二段事务绑定**。不能倒过来的原因写在报告下方「与计划的偏差」。
- `/healthz` 新增 `mediaFetch: { enabled, image, voice:'unsupported-by-helper', disabled, attempted, fetched, unavailable, duplicate, lastReason }`；只有计数与固定原因码，不含路径、消息 ID 或联系人。媒体关闭时该字段完全不出现。
- 开关 `WECHAT_MEDIA_FETCH` 默认关闭；开启时必须给绝对路径 `WECHAT_DATA_PATH` 与 `WECHAT_MEDIA_DIR`，否则**启动即失败**。媒体模块不 import 发送端口（有契约测试）。

### 与批准计划的偏差（一处，已按安全侧选择）

计划写的是「取字节 → 在同一事务里 storeMedia + 登记」。实现时发现 `FileMediaStore.storeMedia` 的前提是消息行已存在（它要用 `message_id` 反查联系人），所以无法在插入消息之前落盘。最终顺序改为两段事务：消息先入库（`media_id=NULL`），再取字节、落盘、绑定。影响：`mediaId` 不再随首次插入写入，outbox 事件 payload 因此不带 `mediaId`。**没有**为此补发第二条 inbound 事件或改 02 状态机——那会引入第二条生成触发路径，风险大于收益；图片消息本来就会被判为需人工处理，本轮不生成候选。真机验收的断言相应是「消息行 + 资产行 + `buildContext` 里该消息带 `mediaId`」。

### 一处新增的安全限制（真机复测前必须知道）

helper 用 nlohmann 按 int64 解析 `msgId`，而请求体是 JSON 数字；**超过 2^53 的 ID 会被 JSON 解析器四舍五入成另一个 ID**。离线复现：`7000000000000000123` 到达 helper 时变成 `7000000000000000000`，也就是会去取另一条消息的图片。桥接因此主动拒绝 16 位以上或大于 2^53 的 ID（`WX_MEDIA_MSGID_UNSAFE`），宁可转人工也不取错。真实 `msgId` 是否在范围内由真机复测回答；超限则需要改协议（例如让 helper 接受字符串 ID）后再开启。

### 本轮遇到的一次环境故障（与产品无关，已排除）

第一次门禁跑到浏览器用例时两条 Chromium 用例（`mock mobile Chromium: edited confirmation payload…`、`…stale confirmation…`）报错，随后重跑时该套件**在 `chromium.launch()` 处挂住**（profile 目录已建、浏览器进程从未出现，8 分钟无进展）。直查根因：本机 `%LOCALAPPDATA%\ms-playwright` **整个目录不存在**，`chromium_headless_shell-1243` 缺失，Playwright 一启动就报 `Executable doesn't exist`。重新执行 `npx playwright install chromium` 后，单个 `chromium.launch()` 348 ms 成功，E2E 随即 31/31 全绿。**这不是代码或测试问题，也没有据此改过任何产品代码**；记录在此是因为"浏览器用例失败"在本机可能再次由同一原因造成。

值得单记一笔的是它的**表现方式**：把 Playwright 指向一个空的浏览器目录、并显式传 `timeout: 8000` 复现时，`launch()` 超过 60 秒仍不返回，超时参数不起作用——所以缺浏览器在这台机器上不是"快速报错"，而是"看起来在跑、其实永远不结束"。以后遇到浏览器用例挂住，先查 `ms-playwright` 是否存在，不要等它。
