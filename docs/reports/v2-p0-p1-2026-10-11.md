# v2 P0/P1 源码交付与验证（2026-10-11）

本轮按用户明确请求执行源码审计及 P0/P1，需求原件保存为 [v2 RFC](../reconstruction-v2-rfc.md)。交付位于分支 `codex/v2-p0-p1`，未批量提交已有脏工作区，没有部署到日常运行副本、迁移日常数据库、操作真实聊天平台或启用真实自动发送。

## 交付结果

P0 已形成 [源码审计与复用映射](../rewrite-audit.md)、[兼容架构](../architecture-v2.md)、[回复管线](../reply-pipeline-v2.md)、[记忆设计](../memory-engine-v2.md)、[迁移计划](../migration-plan-v2.md)、[已实现 API](../api-v2.md)。[当前源码清单](v2-source-inventory-2026-10-11.json)记录443个源代码/配置/测试文件、44191行，含172个测试文件。文件清单是范围和内容校验值，关键路径另按依赖/调用关系审计，不能用行数证明每行都正确。

P1 采用增量方式复用旧消息/事件、聚合、Context 快照、Plan、确认任务、发送任务与账本：

- 新增迁移 `0015_reply_pipeline_v2.sql`，新增按会话版本开关、当前回复任务指针、任务及状态轨迹；旧管线默认保留。
- 新增 `packages/contracts/reply-pipeline-v2.mts` 与 `packages/orchestration/postgres/reply-jobs.mts`，记录批次、revision/generation/policy、快照、trace、候选和审批/发送生命周期；复合外键约束会话/联系人/账号、Plan及快照范围。
- 接入现有 `PgConfirmedService`，补完整批次崩溃恢复、本人自发与撤回/编辑 revision、非法输出拒绝、过期任务与迟到结果隔离、持久化取消和重生成。
- 新增认证 v2 任务查询/trace、按会话启用/回退、审批和取消 API；复用 Owner、CSRF、同源、版本和幂等边界。v1 可继续使用同一 Plan，不绕开新任务 revision 门禁。
- 发送仍由旧 dispatch ledger/Bridge 执行；新任务区分 `SUBMITTED` 与 `SENT`，未知结果为 `UNCERTAIN`，禁止盲重试。即使测试开启 mock auto，v2 也必须人工审批。
- readiness 检查0015的新字段/表；静态核对时修复 `owner-server.mts` 既有类型导入路径与 session 参数类型。本轮未更改网页交互或 Android 源码。

本轮发现并修复两个具体恢复/去重问题：聚合进入生成后原批次被清空，重启仅能找回最后一条消息；同一平台撤回/编辑事件使用新内部事件ID重报，会重复修改会话版本。现在分别使用任务保存的完整 trigger IDs 和平台 mutation 去重结果。

### RFC §9.1 覆盖

| 用例 | 验证方式 |
| --- | --- |
| 同一消息重报10次 | 相同平台消息、不同内部事件ID并发重放；一个有效任务/一次候选生成，无自动发送；旧路径也验证 |
| 三条消息聚合 | 完整批次；模型调用中崩溃后重建，保留三条来源与同一任务ID |
| 生成中追加来信 | 旧任务STALE，迟到模型返回不能形成有效旧Plan |
| 本人发送 | revision增加、旧候选失效，不能批准或发送 |
| 同会话并发worker | 两次首次审批并发、重复审批并发、两个发送worker争抢，只有一次有效提交 |
| API超时未知 | UNCERTAIN，重启后不自动重发，不能伪装成取消成功 |
| 非法JSON/未知action/越权字段 | 当前 PersistentIntelligence 边界拒绝文本/未知action/autoSend/坏候选，FAILED、无Plan/Send；独立Decision JSON Schema仍属P4 |
| 未授权自动发送 | v2即使mockAuto和auto策略同时开启也保持人工审批；真实平台的既有拒绝自动发送用例继续通过 |
| 重启pending/uncertain | PENDING_APPROVAL保持待审批，未知结果保持暂停/权限状态，未新增出站提交 |

额外验证：多段受理/送达回执、撤回/编辑换内部ID重报、审批后新来信取消未提交队列、取消幂等、回退到旧管线、重生成新批次、跨账号同原生ID、跨会话指针外键与错误Owner访问。

## 完成边界与后续

本轮完成的是电脑端 P0/P1 兼容改造与合成环境验收。新管线默认版本1，未为真实联系人启用2；只在隔离测试中演练开关及模拟审批/发送。真实平台验证和部署仍须在明确授权范围内安排，不能由测试通过推断上线完成。

P2 接下来统一 ContextPackage、消息时间/引用/预算、增量摘要和关系状态；P3 复用 facts/evidence 实现记忆提取、冲突/TTL/删除、pgvector+中文检索及来源化风格。当前没有新增长期记忆检索、独立决策模型、手机共用后端或新任务界面，也没有执行 Android 构建/真机验收。P4–P6 的实现、脱敏回放与灰度指标见 [迁移/路线](../architecture-v2.md)。
