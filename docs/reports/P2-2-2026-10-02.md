# P2-2 去标识化试用报告交付

2026-10-02，在 `task/P2-2-trial-report` 开发并由总控合并 main。范围与数据缺口处置见 [审定提案](P2-2-proposal-2026-10-02.md)。

## 使用

本机开发用，只读连接当前应用数据库，不调用模型、不启动平台、不修改状态。提供数据库连接、联系人 UUID 列表和带时区区间；下面的占位值仅在本人本机替换，不能贴入公开报告。默认输出 JSON，`--markdown` 输出可直接粘贴的 Markdown：

```powershell
$env:DATABASE_URL = '<本机 PostgreSQL 连接>'
$env:TRIAL_CONTACT_IDS = '<联系人 UUID 1>,<联系人 UUID 2>'
$env:TRIAL_START = '2026-10-02T00:00:00+08:00'
$env:TRIAL_END = '2026-10-09T00:00:00+08:00'
node scripts/trial-report.mts --markdown
```

可选追加本人本机 JSONL 日志文件路径（最多 20 个、合计 20MB）。有日志不意味着能关联方案。费率没有默认值；需要费用估算时，完整提供 `TRIAL_INPUT_PER_MILLION`、`TRIAL_OUTPUT_PER_MILLION` 和 `TRIAL_CURRENCY`（CNY 或 USD），前两项是每百万 token 的非负平价费率。未提供费率或 token 缺失时费用为 null/数据不足，不能作为供应商实际账单；缓存优惠等另行核验。

## 统计口径

- 区间为 `[start,end)`，按 P2-1 的 `rating.terminalAt` 筛选终态。方案可能在区间前生成；不把生成时间和处理时间混为一谈。
- 直接采用率、编辑采用率、拒绝率均以区间全部五种终态为分母；同时列出重新生成和失效数量。`presented` 不计入。没有终态时采用率为 null，不报告为 0%。
- 联系人只输出按输入列表顺序的序号；方案也只输出联系人内序号；选择输出原候选数组中的位置。不输出内部 ID、身份、正文、引用、模型/provider 的任意标签或原始错误。
- 拒绝原因只输出五种固定代码、未填写、unknown，未知自由文本不会进入报告。统计展示候选数量。
- 编辑幅度为 Unicode 字符点的 Levenshtein 距离 / 原文长度，分条用换行连接，支持中文和表情字符。只统计已选择方案的确认文字；空原文比率未知。大于 4,000,000 比较格或单边 20,000 字符时返回未知，避免无限计算。原文/最终文字只在内存计算，不进入输出对象。
- 模型 JSONL 只识别 `model_call` 和固定数值字段；`at`/`ts` 在区间内、`planId` 明确对应入选方案时才归属。可选 UUID `callId` 用于去重；同 ID 不一致测量拒绝出报告，没有稳定调用 ID 时无法消除重复日志行。
- 一个方案可包含多个替代候选，token/费用属于方案生成，不对每个替代候选重复计费。明确关联的多次调用合计 token/费用并列调用数、错误数与平均调用时延；任一调用 token 缺失时合计 token/费用保留未知，不把部分已知量标成总量。
- 没有模型关联时每个方案的 token/费用/时延为 null；整份报告仅给出不可归属的区间日志行数量，该数量可能包含未选联系人的调用，不能代表所选联系人的开销。
- 区间暂停次数为 null，标明历史源不可用。当前暂停状态和固定原因分布是报告执行时数据库快照，包含全局暂停；不把失效方案数、当前暂停数或 pause epoch 当作区间暂停次数。
- 确认采用不等于提交或送达，不以本报告判定 P1/P2/D08 通过。
