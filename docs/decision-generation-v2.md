# v2 决策、路由、生成、质量与用量（P4/P5）

2026-10-11真实模型测试后，云端决策提示升级为`decision-json-v2.2`，明确reply/wait/skip/ask_user及“审批不等于事实缺失”的语义；注册模型可选`thinking: "disabled" | "enabled"`，未设置则保留供应商默认。该可选参数只应在供应商支持时配置。原160场景复测见[实测报告](reports/v2-real-model-2026-10-11.md)。

实际11题真人评分后，生成提示升级为`generation-three-v2.3`、质量检查升级为`quality-v2.2`，修复第三方助手口吻及内部审批/后台话术外泄；直接询问AI仍须诚实。质量结果契约兼容旧2.1记录。最终40场景追加复测仍有2组质量阻断及1个错误skip；新版真人评分待完成。仅在单独的两位QQ好友候选试用schema启用最新源码和云端，原日常及预发布Core没有替换。见[反馈与试用报告](reports/v2-feedback-2026-10-11.md)。

QQ 新好友真实候选抽查后，当前生成提示为 `generation-three-v2.4`，增加无当前事实时不得补写本人活动的规则；候选页提供活动核对提示及私有试用评价。评价不证明送达、不直接学习风格或长期记忆，最新版真人质量仍待后续评价。见[真人候选质量试用推进](reports/v2-qq-live-feedback-2026-10-11.md)。

`PgConfirmedService` 继续持有唯一审批与发送权威。现有 fake/text Intelligence 工厂暴露只读的 v2 Provider 集合；v1 的 `propose/checkEdited` 接口保留。v2 使用 `ReplyPipelineV2`，按 DECIDING、GENERATING、VALIDATING 分别运行决策、三候选生成/风格处理、确定性质量检查。旧自定义 Intelligence 测试端口保留兼容路径，不自动变成云端供应商。

决策契约和 JSON Schema 位于 `packages/contracts/decision-v2.mts`、`schemas/decision-v2.schema.json`。未知 action、额外执行字段、非法置信度和外部消息证据均拒绝。规则可以提高风险、阻止生成或要求补充事实；模型不能降低本地风险或授予发送权限。默认本地规则不会生成关系事实，`relationship_hint` 是解释数据。wait/skip/ask_user 不调用生成模型，触及停止联系或缺事实时复用原暂停机制。

普通聊天选择 economyProvider，情绪冲突、关系/现实承诺/财务等场景选择 qualityProvider，并强制本人审核。联系人可以指定生成 Provider 或禁止云端；全局禁止云端优先于联系人允许。所有 v2 回复始终人工确认。超时、429、供应商错误可使用明确配置的备用模型；非法决策/候选、质量阻断和认证失败不能借降级绕过门禁。默认不配置备用模型。

每个候选具有独立正文、策略说明以及 natural/playful/direct 风格对应的质量结果。云端提示要求三个不同策略；结构校验拒绝缺少候选、重复正文和执行字段。轻松型在严肃场景应使用温和澄清。无云端配置时 local-fixture 只是开发夹具，不能宣称它具有真实聊天质量。

全局/联系人显式风格设置优先进入生成提示，统计和示例通过实际 ContextPackage 提供。Style Renderer 仅处理用户指定的 emoji 和句末标点，以及有足够样本的句末句号习惯；不截断事实、不增加问题、承诺或经历。长度偏好影响提示与质量审查。v2 不再额外使用旧生成器按最近消息推导的画像覆盖持久化偏好。

质量门禁复用原事实/范围检查，再检查长度、未经确认的敏感行动、隐私披露、常见本人履历/偏好、直接询问 AI 时的虚假否认，以及显式风格和冲突语气。常见本人事实需要本人来源，不能套用对方的第一人称记忆。阻断保留诊断但不创建审批/发送任务；编辑后重新校验，审批事务及发送前再次核对版本、范围和快照。确定性规则不是完整语义事实证明；真实自然度和长尾误判评估属于 P6。

## 配置与注册

现有 DeepSeek 环境配置继续作为 `configured-text` 使用，凭据仍仅在服务端。其他符合 HTTPS chat/completions 协议的模型通过 `AI_V2_PROVIDERS_JSON` 注册。注册格式见 `deploy/models-v2.example.json`；示例中的型号、地址、地区和保留条款均需由部署者填入真实且已核实的值。API Key 使用独立的 `AI_V2_*_KEY` 环境变量，不能写入注册 JSON 或网页。同一数据库的 Core 和 Bridge 应部署相同注册集合与 Owner ID；缺少所选 Provider 时停止生成，不静默切换。

注册集合可以声明 decision/generation 能力、contextTokens/outputTokens，以及可选价格快照：currency、inputPerMillion、cachedInputPerMillion、outputPerMillion、source、effectiveAt。价格由部署者提供，代码不按模型名称猜价格。当前兼容实现参考 [DeepSeek Chat Completions 官方契约](https://api-docs.deepseek.com/api/create-chat-completion/)；其他厂商只有在支持这一契约并验证后才适用，不宣称支持任意 SDK。

Owner 在聊天设置的“模型配置”选择已注册决策、普通/复杂场景生成和备用模型，设置全局/联系人云端权限、等待上限、每日调用/token预算和字数上限。`POST /api/v2/model-config` 用预期版本和幂等键提交整份配置，拒绝凭据、地址、Owner 和发送权限字段。配置改变会让正在生成/待审批任务过期；已有提交/未知发送证据不丢弃。已有明确授权的媒体/Embedding 端口在未保存 v2 配置时保持兼容，显式禁止云端后，v2 新媒体理解、查询向量和后台向量生成也停止外部调用。

Context Builder 使用所选决策、普通/复杂/联系人生成及备用模型容量中的最小预算，保障当前批次和强制边界，再移除低优先级资料。每个 Provider 再检查完整提示和输出预算。超预算停止，不截断当前批次。

## 计量与恢复

迁移0017新增 Owner 配置、幂等命令和模型调用账本；任务增加决策、路由、质量结果。决策/生成调用在发起前保留记录，通过同一 Owner 的预算锁原子预留，避免并行调用超额。记录供应商/模型/声明版本/提示版本、配置版本、路由原因、地区/保留策略、耗时、输入/输出/缓存/推理 tokens、价格快照、费用、错误。只存 IDs 和计量，不存提示正文、回复正文或密钥。

未知 token 保持 null；超时/崩溃时用预留额度约束消费，不能把缺失用量算作零。进程中断留下 running 记录且继续占用当天预算，不能声称供应商是否完成。推理 tokens 单列展示，兼容协议的 completion_tokens 已包含它，费用不重复相加；缓存用量或价目未知时费用也未知。统计近30天调用/错误、P50/P95及按币种的已知费用和平均已知费用；未知费用另计。

这是 v2 决策/候选模型账本。媒体理解和 Embedding 保留其现有独立授权及计量接口，不伪装成这两个任务；统一全部维护调用与长期性能评估留给 P6。记忆来源删除仍使用0016原同步清理机制。

## P5 界面与反馈

响应式网页共用 Core、Owner 会话、任务和发送账本；电脑/手机轮询同一状态。候选编辑保持原草稿管理，v2 审批带会话修订、Plan/Task版本、最终内容哈希和幂等键；结果不确定不会自动重试。读取 trace 不产生审批。发送仅受理、送达和不确定分别展示。

任务卡展示决策风险、路由、质量结果与完整诊断，支持安全取消和为失败/跳过/过期/取消任务创建新批次。重新生成校验最新任务、会话版本、消息有效性、暂停和未决发送，不复活旧任务，UNCERTAIN/SUBMITTED/SENT 均不进入重试路径。记忆中心支持类型/搜索/状态、本人/对方归属、证据、确认/纠正/失效/删除、风格/关系锁定和实际 Context 调试。独立的“回复中使用此联系人已确认记忆”开关复用原policy.factScopes授权，默认不扩大访问范围；本人当前状态/安排可录为24小时有效的临时记忆。事实检查根据记忆归属映射原事实键，不能将对方第一人称事实当成本人事实。

复用 `data_feedback` 保存展示、选择、编辑、拒绝原因；所有消息真实 DELIVERED 后才写送达回执引用、最终内容哈希和字数/改动统计。风格维护仍仅学习本人真实平台文本或真正送达的编辑后文字；仅选择的未编辑模型正文不自动等同本人风格。原生 Android 继续独立运行，本轮 P5 的手机一致性由响应式网页提供，没有更改 APK 或部署运行副本。

P6用量新增按模型/版本/提示/任务/币种聚合，涵盖近30天全量账本，与最近100条明细独立。离线质量/性能证据及真人盲测流程见[P6验收](p6-acceptance-v2.md)，合成fixture通过不能证明真实自然度。
