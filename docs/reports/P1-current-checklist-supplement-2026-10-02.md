# P1 当前验收准备补充（P2-4 启动闸适配）

配合 [P1-1 原清单](P1-1-checklist-2026-10-02.md) 阅读。本页替代其中过时的迁移编号、桥接配置及重启后确认原候选步骤；历史清单不改写。真实操作仍由本人执行，旧 W01 授权已经用完。

## 新配置与启动闸

- 当前迁移到 0012；本机只读样本工具不需要新迁移。
- 桥接新增必填 `WECHAT_PROCESS_ID`，本人核对本次已登录微信的 PID，每次微信重开后更新；两个 DLL 路径仍必填并通过指纹守护。
- 桥接每次启动先写 BRIDGE_RESTARTED、暂停该账号，并使原候选/旧待发送任务失效。即使首次健康探测正常，也要由本人解除 ACCOUNT_FAULT；全局暂停和其他暂停原因需另行处理，未知发送不能绕过。
- 先核对 helper 登录及受控入站。`healthz.watchdog.status=healthy` 只证明探测通过，不证明 hook 完整或送达。探测恢复后总览仍可显示等待本人恢复。

因此，**不能按旧 §5“看候选 → 重启为派发桥 → 确认原待办”执行**。旧候选必须失效；不要删除启动暂停闸、改数据库状态、重放确认命令或重复发送来让旧步骤通过。

## 本人在场的两种准备方式

若本轮目标是只生成一次候选：本人先明确同意在全新隔离验收库中启动具备派发能力的桥接（不是发送正文授权），核对库中没有遗留发送、只有唯一知情好友且是确认模式，再本人配置临时出站/worker 开关并启动。启动后维持暂停，完成 helper/登录/hook 检查，再逐项恢复账号和全局暂停。此后才接收一条真实来信、调用一次模型并查看候选；本人核对最终收件人、原文、单条/单次并点击一次确认。整个候选到确认阶段不重启桥接。后端确认前没有已授权发送任务；候选本身也不构成授权。所有开关由本人当次设置，不改默认配置。

如果本人要求先保持严格只接收，则先按只接收清单查看候选。之后本人授权切换桥接，原候选自动过期。重新确认健康、暂停原因和不存在未决发送，再由本人另行安排第二条获授权的真实测试来信；这会额外调用模型，必须事先纳入本轮预算。已有方案覆盖的旧来信不能通过“为最新来信生成候选”再次利用，当前接口只允许尚未生成方案的暂停文字。最终新候选必须重新核对并授权，不能沿用旧候选正文授权。本轮可能出现两条来信、两次模型调用，报告必须如实记录过期候选与两次费用，不能继续套用原清单“一次 model_call”的结论或通过缩小对账时间段隐藏第一次调用。本人未同意增加来信/调用时就结束只接收轮次，保持暂停，不继续发送。

任一方式出现冲突、未知结果、调用数超限或异常都停止、保持暂停、核查账本，不重试。发送后仍是 RESULT_UNKNOWN；真实好友确认送达后才由本人按原 §6 核对，平台消息 ID 没有就留空。正常/异常退出仍按全局暂停 → 本人卸载 hook → 停进程执行；平台不可达时先停桥接，保留未知事实。

本页是准备说明，未进行本次模型、登录、注入、发送授权，也没有执行真实验收。P3 回显研究工具与 P1 账本对账工具职责不同，前者不能核对或解除未知发送。
