# P4-4c 受控图片理解接线范围审定

总控按本人“继续推进”及开发计划审定本卡。图片当前在 02 已生成并转人工后才获取，04 解释尚未在组合根装配；本卡补齐真实运行入口的顺序与持久化，验收使用合成字节、假 helper/模型和隔离 PostgreSQL。

02 增加可选图片准备端口：锁外获取私有资产，短事务复核原 generation/dependency/pause/global-pause/skill/policy 与 GENERATING 状态后绑定；锁外解释，再短事务复核并通过 03 保存，构建新快照。只有本事务产生的依赖变化可同步更新会话 generation，不吸收其他并发变化。失败沿用 MEDIA_UNCERTAIN 转人工；暂停或新消息使迟到结果失效。04 仅返回 draft，不直接写数据库。已有有效解释（含本人纠正）不重新调用模型。

微信组合根显式启用图片理解时，把获取前置到准备端口；关闭时保留原获取行为。core 可从显式私有目录读取已绑定资产并解释；不获取平台文件。两处默认关闭、只支持本卡的图片确认模式；语音启用在运行入口拒绝。独立媒体预算沿用 P4-3，真实端点不在本卡调用。

可改：`packages/orchestration/postgres/confirmed-service.mts` 与新图片准备模块；`packages/data/media/` 的受限 PostgreSQL 私有读取；`packages/ai/understanding/` 的持久化解释端口与既有解释跳过、`packages/ai/index.mts`；`apps/core/{config,main,runtime,media-wiring}.mts` 及测试；`apps/bridge/wechat-{bridge,main}.mts`；相关 unit/app/集成/架构测试；模块 README、runbook、开发计划与报告。无新增依赖、无迁移、无公共 schema 变更。

验收：接收→获取完整图片→一次解释持久化→新快照→确认候选，无确认零发送；重复/恢复不重复解释；已有纠正保留；失败/缺字节/截断转人工；暂停、新来信、其他依赖变化时零迟到解释/候选；全部门禁 0 fail、0 skip。真实平台字节来源与供应商质量仍由本人后续专项验收。
