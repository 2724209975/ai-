本卡已完成离线开发并通过完整门禁。交付可复用 C++ 查询内核和默认关闭补丁；未构建完整 helper、未替换登记源码或 DLL，未读取真实聊天库、操作平台或调用模型。真实语音获取与理解尚未验收。范围按 [总控审定](P4-5a-proposal-2026-10-03.md) 执行。

## 问题与改动

固定源码的 `GetVoiceBuffByMsgId` 在检查结果非空后直接使用 `result[1][0]`，没有足够的行列检查。其通用 Select/ExecSelect 还丢失原始 SQL 类型，并把 step/finalize 错误当作成功。本卡不修改这条通用路径，独立候选直接使用 SQLite statement 接口读取 BLOB。

内核仅接受规范十进制正整数 ID，最大 `9223372036854775807`。超过 JavaScript 安全整数的 ID 按原字符串拼接经验证的整数 SQL，合成库中的相邻 `9007199254740992` / `9007199254740993` 可区分；超出 SQLite 有符号 int64、浮点/指数/空白/注入形式全部拒绝。此范围是实验限制，不保证涵盖真实微信全部 ID。

调用方给定的数据库快照最多 64 个非零、互不重复的句柄。每库仅读 `Buf`，`LIMIT 2`，所有库只能有一个匹配；后续库错误或重复匹配会丢弃已经取得的候选。必须是非空 BLOB，复制前检查 2 MiB 上限，按显式长度复制，保留 NUL 和全部字节。prepare/step/finalize 错误、异常、NULL/文本/数字、错误列数和异常长度/指针均失败；失败的 Result 不携带 bytes，prepared statement 在所有测试路径被释放。

补丁仅读已登记的规范 `MediaMSG<n>.db` 句柄，不重新调用原始偏移发现路径。默认宏 `WXHELPER_EXPERIMENTAL_VOICE_DB=0`，直接返回空字符串；实验分支才调用内核，并沿用原内部接口的 base64 编码调用。service `GetVoiceByDB`、HTTP 路由和生产语音配置均未接通。补丁中的编码调用经 spy 验证传入准确字节范围，未重新实现或宣称验证上游编码器。

## 限制与下一步

系统 SQLite 的合成 schema/函数签名测试不能证明微信实际 ABI、函数地址、句柄有效性、schema、Reserved0 的语义或句柄快照完整性；也不提供跨库一致事务快照。仅有 `LIMIT 2`/结果字节上限，没有全表扫描耗时硬上限。补丁未开放服务接口，后续必须单独审定鉴权、限流和执行边界。

BLOB 保真不证明这是完整语音容器，更不能直接送 ASR。真实 ID 超出候选范围、Buf 含其他包装或 schema 不同均须重新审定。Silk→WAV、容器校验、供应商及转写接线未做，不把本卡算作 AC 通过。
