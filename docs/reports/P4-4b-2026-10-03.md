本卡完成开发计划中的下一环节：图片入库及图片模型请求前，验证完整容器和全部像素能否解码。完整门禁 **485 pass / 0 fail / 0 skip**。范围与依赖变更经总控在 [提案](P4-4b-proposal-2026-10-03.md) 审定；本卡不调用真实平台或付费模型。

## 改动

- `packages/data/media/image-validation.mts`、`image-validation-worker.mjs`：共享 PNG/JPEG/单帧 GIF/单帧 WebP 校验。父进程检查完整边界，独立子进程用 sharp 强制解码全部像素；拒绝截断、损坏、格式不符、尾随内容、动画与不支持格式。PNG 动画扩展显式拒绝，避免只取首帧。
- `packages/data/media/bounded-image-file.mts`：按文件描述符限量读取并复核大小、修改时间，避免外部 stat 后文件增长导致无界读取。
- `packages/platform/wechat/media-acquisition.mts`：同一总时限内覆盖 helper、轮询、读取与解码；未写完的图片继续等待，重复坏字节不反复解码。验证后再次读取并比对原始哈希；发生变化须重新验证。保留完整原字节，不重编码；一次获取只请求一次 helper。
- `packages/ai/understanding/vision-provider.mts`：请求前复制输入并执行共享验证，无效或取消的输入不调用模型端点；等待期间调用方修改原缓冲区不会替换已验证的上传内容。
- 新增共享验证器测试与 `tests/fixtures/media-images.mts`，更新获取/provider/PG 集成测试及架构守护（含 `.mjs` 子进程）；同步模块 README 和 runbook。
- 根依赖精确锁定 `sharp@0.35.5`，锁文件包含其平台原生可选包；安装时审计 0 vulnerabilities。**无新增迁移、无公共契约变更**。

## 资源与失败边界

输入最多 10 MiB，最多 16,777,216 像素、4 通道；每个父进程最多同时运行 2 个解码子进程，忙时直接拒绝，不排队。共享验证默认 5 秒、最大 10 秒；像素解码另设 3 秒限制，父进程硬时限覆盖启动和元数据解析。图片获取默认总时限 8 秒，配置不得超过 120 秒，解码服从剩余总预算。取消或超时会终止本轮子进程，等退出后才释放并发名额。

子进程只继承基本系统/临时目录/语言环境，不继承模型密钥、数据库地址或 NODE_OPTIONS；通过 IPC 接收有限字节，只返回宽高/成功状态，不输出原生错误细节和像素。进程隔离与这些上限不是操作系统级沙箱，也不构成原生内存硬配额。

BMP、APNG、多帧 GIF/WebP 当前拒绝。共享验证器支持静态 WebP，但本卡没有增加微信 `.dat` 的 WebP 识别能力。可完整解码仅证明当前文件字节有效，不能证明其是平台真正的原文件，也不能证明图片语义理解正确。

## 限制与下一步

本轮只验证 Windows 本机原生依赖。其他宿主必须安装对应 sharp 原生包并重新运行门禁，不能跨系统复制 node_modules。完整解码在获取和模型请求前各执行一次，有额外 CPU 与启动开销；当前明确限制并发，不承诺高吞吐。
