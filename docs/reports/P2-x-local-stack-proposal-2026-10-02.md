# P2-x 本机完整启动与异常恢复演练：任务卡与总控审定

本人授权按推荐顺序继续推进，先完成整组模拟演练，再本人执行 P1。总控新建本卡并批准 scripts/、tests/integration/、tests/fixtures/、当前开发计划与本卡报告、deploy/runbook.md 的必要同步。无新依赖、公共契约或迁移，0013 保持未分配；已交付历史报告不改写。

目标：复用生产常驻入口的真实子进程驱动，实际启动隔离 PostgreSQL、生产核心与直接复用 createWxBridge 的独立 fixture 桥接/helper；模型使用持久假实现，全部平台身份/消息/发送传输为合成。生产入口不得增加跳过 DLL 指纹、替换 helper 地址或关闭启动暂停的环境开关；测试只通过模块级依赖注入指定 fixture 组合根。

验收：真实顺序启动/迁移/健康，数据库、核心、桥接异常退出后逆序停止和退避重启；外部端口占用和外部集群不被接管/停止；显式停机无重启、无遗留子进程；启动与恢复后全局/账号暂停、旧已确认未提交任务不补发、未知发送不重试。完整门禁 0 fail/0 skip，报告实际进程/模拟平台边界。

允许修复演练暴露的进程所有权、就绪取消、资源清理与监督循环问题。父进程只停止已核实属于自己的子进程；重启任何部分不得放宽未知发送或暂停。只使用本卡新建的隔离集群/私有临时目录，不连接现有业务数据库；不启动微信、注入/卸载 helper、登录、联系好友或调用付费模型。

## 原生数据库故障方式与边界

Windows 单杀 postmaster 的初次整组演练暴露端口/连接未收拢问题；独立 probe 对照确认，关闭仍持有连接后端口才可重新绑定，原生 immediate 停止能回收所属后台进程并重启。总控据此把数据库崩溃恢复验收具体化为“校验本轮 PID 后使用 pg_ctl immediate，重启执行 WAL 恢复”；核心和桥接仍实际硬杀。不得把单杀 postmaster 自动恢复判通过，也不得放宽端口/集群保护来掩盖失败。该进程树路径作为明确未完成项写入报告/手册，P1 出现任一异常即停止本轮。测试用例命名需明确区分两种方式。
