# 03 持久数据 provider 续作

日期：2026-09-23。公共契约 v0.3.0，已发布迁移 0001/0002 **未修改**。本轮只修改 `packages/data/**` 与本报告。

## 已接入

- `packages/data/postgres/provider.mts` 接受总控 `PgClient` 的调用方事务。消息写入和平台键去重、事实新增/确认/纠正/过期/删除、消息删除传播、分析证据写入、快照创建、依赖 epoch 增加、快照标失效及 outbox 事件均使用同一个事务客户端；由 02 在外层同时提交 inbox/control 副作用。持久写入使用 `0002_data.sql`，不另造表。
- 03 的数据变更和快照读取使用与总控 `withDispatchLease` 相同的 advisory 边界。发送前接口 `readContextProjection(tx,{callerContactId,contactId,snapshotId,allowedScopes,expectedDependencyEpoch})` 在 02 的 lease/事务内同步复核 epoch、快照状态、消息/事实/分析版本、事实当前有效期及 scope，失败返回 `STALE_CONTEXT`。02 仍负责 generation、policy、授权、发送任务与最终 preflight。
- `packages/data/postgres/context-repository.mts` 使用已发布 0002 的 `platform_order_key` 排序，按联系人和 scope 限定消息、事实、检索和分析 SQL。正式 provider 每次 scoped 操作在事务内执行 `setContactScope`；调用方不能仅靠自报联系人 ID 取得另一联系人的正文。
- `packages/data/postgres/provider.integration.mts` 是与 07 PostgreSQL 门禁配套的真实库用例：隔离 schema、受限非 BYPASSRLS 角色、重复消息、事务回滚、epoch/outbox、旧快照失效、跨联系人检索/直接 SQL、事务结束后无 scope 的 global fact。需要 `TEST_DATABASE_URL` 指向允许创建临时 schema 与角色的隔离 PostgreSQL 17 测试库。

## 07 RLS 与新编号迁移条件提案

07 指出 `0002_data.sql` 的 `data_facts_scope` 使用 `current_setting('app.contact_id', true) IS NOT NULL`。若事务结束后该 GUC 为空字符串，global fact 可能在无 scope 时可见。07 和本轮 03 用例均要求“提交后无 scope 读取 global fact 为 0”；当前未在真实 PostgreSQL 上执行，故问题尚未被本轮证实。

**若 07/03 真实 PostgreSQL 17 用例复现 `RLS_SCOPE_LEAK_AFTER_COMMIT`，向架构总控提议新编号 `0003_data_scope_fix.sql`，不改写 0002：**将 facts 策略的有效 scope 条件改为 `NULLIF(current_setting('app.contact_id', true), '') IS NOT NULL`，并检查所有联系人表的 `USING/WITH CHECK`、受限运行角色以及清空 scope 后的直接 SQL。兼容策略是先暂停数据/发送 worker，执行新迁移并复跑受限角色负测；回滚只能通过后续迁移恢复策略，不能改历史迁移。影响 AC09、21、31；总控审批编号和 SQL 后由 07 执行迁移测试。
